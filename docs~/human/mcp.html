Connect

Unityを開いてCodexへ登録する

  1. ee4vを導入したVRChat ProjectをUnity 2022.3で開きます。
  2. ee4v / MCP / Log Connection Informationを選びます。
  3. Consoleに表示された設定をCodexのconfig.tomlへ追加します。
  4. Codex側でMCPを再読み込みし、ee4v_server_statusを呼びます。
[mcp_servers.ee4v]
url = "http://127.0.0.1:48884/mcp"

通常のUnity起動ではserverが常に自動開始します。現在のEditor sessionだけ停止する場合はee4v / MCP / Stop Server、再開する場合はee4v / MCP / Start Serverを選びます。停止後も次回の通常起動では自動開始します。バッチモードでは開始しません。

Scope

Avatar改変をまとまりとして操作する

領域主な操作
AvatarSceneとPrefab ModeからAvatarを探します。調査は構成と数量、監査は対処が必要なfindingだけを返します。
表情BlendShapeとClipの統合調査、静止表情Clipの作成・更新、表情animationのポーズ追加・編集・並び替え・削除、検証・時刻指定preview・remap、Gesture 1組への割り当て、FacialSetのplan、dry-run、適用を行います。
Asset ManagerItem検索、File解析、名前・説明・Tag・Archive、Target、Dependency、既存Collectionに加え、取り込み済み実Prefabの比較と構造調査を行います。Eagle由来Itemの名前と説明はEagle側で管理します。

Asset preview

候補だけを実Prefabで撮影して比べる

  1. ee4v_asset_searchで名前、説明、TagからItemを5〜10件へ絞ります。
  2. ee4v_asset_get_itemのprefabCandidatesから、Project内に存在するPrefabを確認します。
  3. ee4v_asset_render_prefab_previewを同じviewとsizeで呼び、実PrefabのPNGを比較します。全周比較にはturntableを使います。
  4. ee4v_asset_inspect_prefabでRenderer、Material slot、Shader、Texture、Mesh、BlendShapeと参照切れを確認します。
  5. 返されたRenderer pathとMaterial pathを既存Unity MCPへ渡してMaterialを編集します。

未ImportのAsset: ZIPやunitypackageにPrefabが入っていても、Unity ProjectへまだImportされていなければpreviewできません。MCPは自動Importせず、候補なしと理由を返します。

撮影ではサムネイルを拡大せず、Unityの隔離Preview環境へPrefabを読み込みます。カメラは各方向から見た境界の横幅と縦幅に合わせてフレーミングします。Play Modeへ入らず、SceneやPrefab assetを変更しません。PNG cacheはdependency hashごとにAssets外へ保存され、Prefab、Mesh、Material、Texture、Shader、Variant親が変わると再利用されません。

Workflow

発見、plan、適用、監査の順で進める

  1. ee4v_find_avatarsで現在の対象とavatarRefを取得します。
  2. 構成や数量が必要ならee4v_inspect_avatar、問題点が必要ならee4v_audit_avatarを使います。
  3. 表情は対応するplanまたはdryRunで変更内容を確認します。
  4. 書き込みtoolを承認して適用します。
  5. 最後にもう一度Avatar監査と必要なpreviewを実行します。

AvatarのGameObjectを選び直した場合やUnityを再起動した場合は、以前の参照を使い回さずee4v_find_avatarsから始めます。表情previewは描画可能なSkinnedMeshを必要とし、見つからない場合は空の画像を成功扱いにせず明示的なエラーを返します。

Writes

再適用できる単位で変更する

  • 静止表情Clipはcreate、patch、replaceを明示します。複数ポーズClipはanimation専用toolで編集し、静止表情toolでは上書きしません。
  • 表情animationはee4v_inspect_expression_animationでポーズindexとrevisionを取得し、追加・更新・並び替え・削除・Loop設定を行います。書き込み前にdryRunを使用し、共同編集時はrevisionも渡します。参照Clipを設定したポーズと直接編集するchannel値は同時指定できません。
  • ee4v_render_expression_previewへtimeを渡すと、各ポーズまたは遷移途中をPNGで確認できます。
  • 表情remapはRenderer pathとBlendShape名の完全一致を優先し、一致しないchannelだけpresetの役割と左右で対応付けます。FacialSet適用はdryRunで設定と前提条件を検証できます。
  • AssetManagerでは変更前の値を先に取得します。Eagle由来Itemの名前と説明はEagleで変更します。同期、削除、File登録、Import、新規Item／Collection作成はMCPに公開されないため、必要な場合はAssetManager画面から実行します。

Security

localhost専用として扱う

serverは127.0.0.1だけで待ち受けますが、認証はありません。同じPC上のprocessは接続できるため、port forwarding、reverse proxy、LAN公開は行わないでください。

書き込み承認: Codex側ではread-only toolと書き込みtoolを区別し、内容を確認してから書き込みを承認してください。dryRunがある操作は先に利用します。

Unity MCP

汎用操作は既存Unity MCPを使う

ee4v MCPはAvatar固有の規則をまとめた操作に使います。Hierarchyの一般編集、任意ComponentのSerializedProperty、SceneとPrefab、Animator Controller、MaterialとShader、Console、Play Mode、screenshot、build、任意C#実行は既存Unity MCPの担当です。
