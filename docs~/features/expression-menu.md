# Expression Menu

`src/Editor/Feature/Avatar/ExpressionMenu`の`Ee4v.ExpressionMenu.Editor`は、Unity 2022.3 / VRChatでギミック制作とExpression Menu編集を扱います。AssetManagerの「Expression Menu」カテゴリと単独の`ee4v/Window/Avatar/Expression Menu`が同じ`ExpressionMenuView`を使用します。動作確認はPlay Modeの既存GestureManager Controlsで行います。

## ギミックエディター

`ExpressionMenuView`は1ペインで全体画面と個別編集画面を切り替えます。全体画面は利用可能な横幅を使用し、円形メニューの列と表示中の項目の簡易編集カードを横に配置します。カードは最大480px幅で画面幅に応じて複数列に折り返し、狭い幅では円形メニューの下へ配置します。96pxのアイコンプレビュー・Texture選択欄、名前の入力欄、「詳細を編集」を配置します。Submenuには「サブメニューを開く」も配置します。現在開いているSubmenu自身の名前・アイコンは円形メニューの下で編集できます。名前・アイコンだけの変更は型、parameter、初期値、同期設定や動作を変更しません。円形メニューのItemまたは「詳細を編集」で個別編集画面へ移動し、円形メニューは表示しません。個別編集の内容は最大680px幅で中央配置し、スクロール領域の外の左上へ「メニューへ戻る」を配置します。同じ階層・ページの全体画面へ戻り、編集内容を保持します。

個別編集では上部の枠内に144px幅のアイコン、その右に名前・タイプ選択・初期値を縦に配置し、動作カードを枠の下へ配置します。アイコンプレビューの下にTexture選択欄を内包し、枠全体でTextureのドラッグ＆ドロップを受け付けます。アイコン未設定時はUnityのGameObjectアイコンを表示し、全体画面と円形メニューも同じ代替アイコンを使用します。保存値と選択欄は未設定のまま保持します。操作タイプは見出しを表示せずツールチップで示し、説明文と未設定時の案内文は配置しません。同期は各動作カードへ配置します。生成Submenuには名前・アイコンと項目削除を表示し、対応する動作エディターを持たない通常項目は既存の詳細フォームで編集します。統合画面は専用ExpressionMenuHostで他カテゴリのプレビュー・設定領域と切り替えます。単独Windowの最小幅は480pxです。

円形メニューの「＋／追加」はItem／Submenuの二択を表示します。ItemはToggleを初期タイプとした、動作が空の専用Prefabを作成し、表示中のrootまたはサブメニューへ即時登録して個別編集画面を開きます。タイプはToggleと0〜100の二択で、追加直後から初期値と動作の追加を編集できます。「動作を追加」は動作セクションの見出しに配置し、選択タイプへ対応する動作だけを列挙します。同じ種類を複数追加でき、各カードの「動作を削除」でその動作だけを除去します。最後の動作を削除してもメニュー項目は残ります。全動作は1つのMenu Itemと固有パラメーターを共有します。

| 操作タイプ | 利用可能な動作 | 初期状態 |
| --- | --- | --- |
| Toggle（ON／OFF） | オブジェクト表示／非表示、マテリアル差し替え、BlendShape変更、Animation Clip | ON／OFF |
| 0〜100（連続値） | BlendShape変更、Animation Clip | 0〜100の数値 |

他プレイヤーへの同期は動作カードごとに設定します。ONの動作は他プレイヤーにも適用し、OFFの動作は本人だけに適用します。同じItemに両者を組み合わせられます。動作の新規追加時は同期ONです。既存のMA ReactiveComponentやClip動作がある項目はToggleとして扱います。

Toggleと0〜100の切り替えは、破棄対象がある場合に表情のジェスチャー割り当てと同じ共通`ConfirmationOverlay`で確認します。中立色の本文と区切り線のある操作欄を使用し、赤い「破棄して変更」を左端、通常の「編集を続ける」を右端へ配置します。動作カード・生成MA ReactiveComponentがなく、現在の初期状態がOFF／0の場合は確認せず即時に切り替えます。名前・アイコンだけの編集では確認しません。追加済みの空の動作カードも破棄対象とします。確認中はタイプの表示と保存データを元のまま保持し、背後のWindowを操作できません。「破棄して変更」で初期状態をOFF／0へ戻し、すべての動作カード・対象・Clip参照・動作ごとの同期設定と生成MA ReactiveComponentを除去して、新しい型のparameter・Controllerを構成します。名前・アイコン・メニュー登録先・固有parameter名・値保存設定と素材Clipは保持します。「編集を続ける」またはEscは変更せず閉じます。画面を離れた場合も確認を取り消します。失敗した場合はUndo transactionで元へ戻し、overlay内にエラーを表示して元のタイプに留まります。確定した変更はUndo／Redoの対象です。

Itemの個別編集は選択した項目の出所MA Menu Itemを参照します。Toggleでは「初期状態をONにする」、連続値では「初期値（0〜100）」で全動作共通の初期状態を設定します。名前・アイコンやタイプを更新しても個別編集画面を維持し、全体画面へ戻ると更新された円形メニューと簡易編集行を表示します。メニュー未登録で保持する操作は設けません。

画面表示・再描画だけでは既存データを変更しません。メニュー未登録の項目は編集元候補へ含めません。個別編集の項目削除は、生成したギミックのScene上のGameObjectと付属componentをUndoで除去して全体画面へ戻ります。メニュー未登録のScene上の定義は残しません。保存済みassetは保持します。既存の対応MA項目も個別フォームで扱いますが、動作カードの追加・削除はee4v生成Prefabだけに許可します。

## ItemとSubmenuの作成

Item・Submenuとも現在のrootまたはサブメニューへ追加し、出所componentで階層・ページを特定します。Itemは個別編集画面を開きます。SubmenuはMA Children構成で作成し、作成後にその階層の全体画面へ入ります。その中の「＋」から再びItem／Submenuを追加できます。生成Submenuへparameter・同期・既定値・型切り替えなどの動作用設定は表示しません。

専用PrefabはMA Menu Itemを使用します。ItemはToggle、空の動作設定で作成します。保存用ControlはToggle、固有パラメーター名、値1、同期・値保存あり、初期OFFです。タイプ選択でToggleまたはRadialPuppetへ更新します。初期状態は個別編集で変更できます。SubmenuはSubMenu型、空parameter、値0、同期・値保存・既定項目なしで作成します。`MenuSource`はChildrenにします。動作テンプレートの選択はItemの「動作を追加」だけに配置します。

Toggleの表示／非表示・マテリアル差し替え・BlendShape変更はEditor専用recipeの`MenuReactiveAction`へ保持し、カードごとのON/OFF ClipとFXレイヤーを生成します。Object Toggleは対象とON時の表示、Material Swapは変更前後のMaterial、Shape Changerは対象SkinnedMesh・BlendShape・ON時の値（0〜100）を編集します。いずれも対象行を追加・削除できます。対象行の編集は全体の初期ON/OFFを変更しません。Material Swapは変更元と変更先のObjectFieldを矢印で結び、見出し付きの2列を1行に配置します。新規Material Swapはアバター全体を対象とし、指定した元Materialを使用する各Rendererのslotへ変更先を割り当てます。OFFは設定時の値へ戻します。

既存のMA ReactiveComponentは最寄りのMenu Itemに属するものだけをフォームへ表示します。ee4v生成項目でrecipeを変更すると、既存の対象・値・反転と同期設定をrecipeへ引き継ぎ、元componentをUndo付きで除去します。描画だけでは変換しません。Quick SwapとBlendShape削除は変換を拒否し、元の設定を保持します。既存の外部MA項目はcomponentの設定編集を維持し、動作単位の同期変更と動作カードの追加・削除は許可しません。

全動作はメニューの共通BoolまたはFloatを参照します。同期ONの動作が1つ以上あるときだけこのparameterを同期し、すべてOFFならローカルparameterとして構成します。同期OFFの動作レイヤーはmotionを持たないLocalOnly stateを既定とし、組み込みBool `IsLocal`がtrueのときだけ動作stateへ遷移します。他プレイヤー側ではそのレイヤーからプロパティを書き込みません。初期ONや連続値の初期値がある場合も同じ条件を適用します。共通parameterとカードごとの同期フラグ・レイヤー制御により、同期動作と本人専用動作を1つのメニューで操作します。

連続値のBlendShape変更は、対象SkinnedMesh・BlendShapeと「範囲」を指定します。「範囲」は2つの数値入力を区切り記号とともに1行へ並べ、左を操作値0、右を操作値100でのBlendShape値として扱います。各入力のtooltipで両端の意味を示します。複数の対象行を追加・削除でき、両端の値は0〜100で検証します。逆方向の範囲も指定できます。1秒の線形Clipを生成し、共通Floatパラメーターの値でサンプルするFXレイヤーを生成します。連続値では表示切り替えとMaterial差し替えのテンプレートを表示しません。BlendShapeとAnimation Clipの動作カードに常設の説明文は表示しません。

対象未指定の行を保存・再読込した場合や、指定pathにSkinnedMeshRendererが存在しない場合も編集欄を保持します。Unityのmissing-component参照は実際のnullへ正規化し、meshへアクセスせず対象の再指定・行削除を行えるようにします。

MA対象は編集中アバター内部に限定し、rootの無効化を拒否します。対象をroot相対pathのAvatarObjectReferenceへ変換し、同名の兄弟Objectと名前に`/`を含むObjectを拒否します。対象の削除・改名、存在しないBlendShapeはエラー表示します。

## Animation Clip

Animation ClipカードはReactiveComponentテンプレートに限定しない動作の入口です。アバターroot相対の通常ClipをON/OFFで指定し、プロパティ操作・エフェクトなどを同じメニューで切り替えます。OFF省略時はONが操作するプロパティについて設定時のアバターの値を取得し、復帰用Clipを生成します。ON/OFFの片方だけにあるプロパティも、もう片方に設定時の値を補います。素材Clipは変更しません。ON未指定のカードはControllerへ含めません。

設定は専用Prefabと同じフォルダのEditor専用`Gimmick.asset`へ保持し、空のギミックの識別にも使用します。`Gimmick.controller`へカードごとのFXレイヤー、ON/OFF stateとClipのコピーを生成します。共通Boolパラメーターで即時遷移し、Write DefaultsはOFF、レイヤーweightは1です。MA Merge AnimatorをAbsolute path / FX / Appendで接続します。初期ON/OFF変更はControllerのparameter defaultと初期stateにも反映します。最後の有効Clipを外すと生成Merge Animatorを除去します。

連続値ではON用Clipだけを指定し、操作値0で先頭、100で末尾をサンプルします。生成コピーのloopTimeを無効にし、FXレイヤーの単一Value stateへmotion time parameterとspeed 0を設定します。素材Clipは変更せず、OFF用参照は保持したままフォームから隠します。時間経過での再生は行いません。生成ControllerのFloat defaultは初期値を100で割った値です。RadialPuppetの主parameterは空とし、subParametersの先頭へ固有パラメーターを設定します。同じGameObjectへMA Parametersを配置してFloat・明示的default・値保存・localOnly（同期設定の反転）を指定します。動作が未設定でもこのparameter設定は保持します。Toggleへ戻すと生成したFloat設定を除去します。

Legacy／Humanoid Clip、解決できない対象・プロパティ、アバターrootの表示操作、同名pathを拒否します。生成する全動作カード間で同じプロパティを操作することも拒否します。外部Clip変更後はカードでClipを再指定して生成物を更新します。動作確認はPlay Modeで行います。

Clip入力時は、変更の確定とUndo記録の前に、対象Object・Component・BlendShape・プロパティの存在と全動作間の競合、復帰用Clipの生成を検証します。存在しないComponentへAnimationUtilityでアクセスしません。不適合なClipは入力欄を元の参照へ戻し、同じ編集欄にエラーを表示します。対象を解決できない場合はClip名・対象path・Component型・プロパティを添えます。保存済みrecipe・Controller・Prefabと選択中のメニュー、動作カードを保持します。

## BlendShapeの選択

Toggleと連続値は共通の対象選択フォームを使用します。対象行ごとにSkinnedMeshRendererのObjectFieldと、そのmeshのBlendShape名を列挙するドロップダウンを縦に配置します。対象未指定時はBlendShapeの選択を無効にし、Renderer変更時は最初のBlendShapeを選択します。Toggleはその下に「OFF → ON」の2つの数値欄を1行で表示します。OFFは選択したRendererの現在のBlendShape値を読み取る編集不可の欄で、対象とBlendShapeの選択後に更新します。OFF値はrecipeへ保存せず、生成Clipの復帰値も設定時の現在値から取得します。ONだけを0〜100で編集します。連続値は2つの値を1行にした範囲入力を表示します。「対象を追加」「対象を削除」で複数の対象行を編集し、対象とBlendShapeが未指定の行も保持します。未設定の行はClip生成から除外し、指定後に動作へ反映します。既存の対象と値は描画だけでは変更しません。指定済みの対象やBlendShapeが消失した場合はエラーを表示し、再指定と行削除を行えます。不正な値や更新失敗時は入力欄を元に戻します。

## 表示と出所

統合画面と単独Windowは3Dプレビューを表示せず、1ペインの全体画面と個別編集画面を使用します。統合画面は合成表示に固定し、単独Windowの全体画面だけに表示・編集元の選択欄とメニュー名を表示します。説明用HintBox、再読み込み・メニューasset保存ボタンは配置しません。編集エラーと読み取り専用の案内は必要時に表示します。選択と変更の後にメニューを解決し直します。

初期表示はDescriptorへMA Menu Installer、Menu Item、Menu Group、Menu Install Targetを解決した構成です。円形メニューはGestureManagerの`GmgCircleElement`、`RadialMenuUtility`、`RadialCursor`を使用し、300pxの円、100pxの中央円、50pxのアイコン、扇形のグラデーション・区切り線・設定色・カーソルを描画します。root初期ページには項目と追加またはNextを表示します。階層内と2ページ目以降は「戻る」を先頭へ配置します。時計回りに項目、末尾操作の順で均等に分割します。

8項目超の合成メニューは7項目とNextへ分割します。Nextがあるページの末尾はNextだけ、最後のページだけに「＋／追加」を配置します。簡易編集行も現在のページの項目だけを表示します。追加後は該当項目のページを保持して個別編集を開きます。追加・戻る・Nextはassetの8項目上限に含めません。ページ移動は表示だけで元assetを分割しません。

保護・読み取り専用・出所不明の項目は名前・アイコンの入力と詳細編集を無効にします。円形プレビューでも編集だけを行うItemは文字・主アイコン・型の補助アイコン・扇形をグレーアウトします。Submenuは保護状態にかかわらず円形メニューと「サブメニューを開く」から移動でき、ホバー強調も有効です。右クリックの「項目の設定」は編集不可の場合に無効表示します。移動先の各項目の編集可否はその出所から個別に判定します。Scene componentは対応する元Prefabも`AssetDatabase.IsOpenForEdit`で確認します。生成ギミックの編集データ・Controllerも書き込み可否を確認します。AssetProtectionへ直接依存せずUnityの編集許可APIで保護を反映します。個別画面の入力にも編集可否を反映します。追加・登録は元メニューassetを変更せず専用PrefabとMA Menu Installerへ保存するため、参照先メニューassetが保護されていても許可します。Children rootが編集不可なら追加・登録を無効にします。Prefab編集不可とPlay Modeでは変更を無効にします。

編集可能な項目のホバー・フォーカスはGMの選択色と1.1倍の拡大で強調します。アイコン・文字は入力を受け取らない表示レイヤーに分離し、無効状態も反映します。ラベルは`UiTextFactory`の12px・100px幅で折り返し、切り捨てません。固定した扇形でホバー判定し、表示レイヤーだけを拡大します。状態変化時だけアニメーションを開始し、反転・破棄時に停止・解放します。未設定アイコンはUnityのGameObject、階層の戻る・型の補助アイコンはGM、個別編集の戻る・追加・NextはFluent UI System Iconsを使用します。

編集可能なサブメニューは円形メニューのクリックでその階層の全体画面を開きます。子のItemを選ぶと個別編集へ移動します。Submenu自体を編集する場合は簡易行の「詳細を編集」または右クリックの「項目の設定」を使います。現在開いているSubmenuの個別編集から戻ると同じ階層へ戻り、削除・SubMenu以外への変更は親の全体画面へ戻ります。

単独Windowの「表示・編集元」でDescriptorとMA Installerの参照asset、MA Menu Itemを選択できます。合成項目は名前・型・アイコン・値・parameter・Puppet軸・ラベル・サブメニューから出所を照合します。複数候補は合成表示で無効にし、編集元選択で確定します。元Controlが差し替わった場合も変更を拒否して再選択を促します。

通常項目は編集元Object、名前、アイコン、ControlType、parameter、value、subMenu、PuppetのsubParametersと方向ラベル・アイコンを設定できます。通常MA Menu Itemは同期・値保存・既定項目・自動値も設定できます。MA Childrenは子構造を保持し、subMenu assetへ置換しません。共有assetの編集はすべての利用アバターへ影響します。

## 専用Prefabと保存

Coreの共通アセットルートの`Animation/ExpressionMenu/<アバターPrefab名>/<ID>/MenuItem.prefab`へ項目ごとのPrefabを作成して接続します。アバター直下には`<アバターPrefab名>_ExpressionMenu`というまとめ用rootを1つ配置し、別IDのフォルダーの`ExpressionMenu.prefab`へ保存・接続します。同名Objectがあれば別名で作成し、再利用は名前ではなく生成Prefabのasset pathで判定します。まとめ用rootへメニュー用componentを追加せず、その子へrootとassetサブメニュー向けの項目Prefabを置いて各MA Menu Installerで登録します。assetサブメニューは`installTargetMenu`を指定します。MA Childrenはその子rootへ置いてChildrenの取り込みを使用します。生成したSubmenuの親子構造はまとめ用root内で維持します。既存の外部MA Childrenへ追加する場合も、そのChildren rootへの配置を維持します。親も生成Prefabなら子の追加・削除時に親Prefabの子構造も保存します。

rootまたはassetサブメニューへの追加時は、アバター直下にSceneの追加overrideとして配置された編集可能な生成Item・Submenuも、子構造と登録先を維持してまとめ用rootへ移します。画面表示だけでは移動せず、保護された項目とアバターPrefabから継承した階層も移動しません。まとめ用rootの作成・項目の移動・追加は同じUndo groupへ記録し、失敗時は巻き戻します。各ItemのrecipeとControllerの保存先・Prefab接続を維持します。

生成Prefabの保存は対象root内の追加・削除とObject overrideを、その生成Prefabのasset pathへ個別Applyします。外側のAvatar Prefabへ一括Applyしません。生成rootはitem一覧から除外し、アバターの配置と他の改変内容の保存は引き続きホスト側が扱います。

書き込み可能な通常SceneのAvatar Prefabインスタンスが対象です。まとめ用rootを含む生成Prefabは上部item一覧から必ず除外します。`assetManager.excludedItemNamePrefixes`は大文字小文字を区別しない名前接頭辞リストで、アバター直下のPrefabを追加除外します。既定は空で、表示対象の指定だけに使用します。

入力確定と選択・チェックの変更で即時適用します。文字・数値はEnterまたはフォーカスを外した時に確定します。設定・動作追加削除・Clip編集・生成Controller・初期状態をUndoへ記録します。専用PrefabとEditor設定・Controllerを保存し、Prefab overrideと作業Scene変更をホストへ通知します。既存メニューassetはそのassetを保存します。配置と既存Scene componentはホストのAvatar Prefab保存を使用します。通常生成項目の削除はGameObjectと付属component、既存MA Menu Itemの削除はそのcomponentだけを除去します。Scene、Git、DBは機能側で保存しません。

## 依存

Coreの公開Localization・ProjectAssetSettings、UI、共有AvatarEditingの編集許可・変更通知・単独Windowへ依存します。設定サービス型のためCore.Contracts、BodyPartCategoryのためCore.Editorも参照します。AvatarEditingは統合版・単独版の対象と保存契約を揃えるため使用します。他のAvatar機能へ参照しません。VRChat SDK、MA runtime、GM runtime / Editorの実際に使うassemblyのみ参照します。GMは描画の共用に使用し、Edit Modeでアバター実行モジュールを生成しません。

MAは`src/package.json`の対応範囲（1.18.2以上2.0.0未満）で内部resolver `VirtualMenu.ForAvatar`、`RootMenuNode`、Childrenのnode keyへアクセスします。バージョン依存箇所はExpressionMenuModelへ隔離します。resolver取得・解決失敗時はエラーを表示し、不完全な合成メニューへの編集へ代替しません。

## 手動確認

Unity 2022.3で以下を確認します。新規自動テストは追加しません。

- 1ペインの縦スクロール、全体画面と個別画面の切り替え、3Dプレビュー非表示、カテゴリ切り替え、単独Windowの表示元切り替え。
- 全体画面が横幅を使用し、円形メニューの隣に最大480px幅の簡易編集カードが複数列で並ぶこと。狭い幅では円形メニューの下へ折り返すこと。個別編集の戻るボタンがスクロール領域外の左上にあること。
- 個別画面が最大680px幅で中央配置されること。全体画面で名前・アイコンを変更でき、型・parameter・動作・初期値・同期設定が保持されること。個別画面では円形メニューがなく、上部枠内に大きいアイコン、その右に名前・タイプ・初期値、枠の下に動作があること。説明文が表示されないこと。アイコン選択欄がアイコン枠内に収まり、選択・クリア・ドラッグ＆ドロップ・Undoで表示と保存値が一致すること。未設定時は円形メニューと同じGameObjectアイコンを表示すること。狭い幅での折り返しと入力欄の収まり。個別編集から戻ると同じ階層・ページを表示し、項目削除後は全体画面になること。Submenu移動では現在のSubmenuの簡易編集行を表示すること。追加がItem／Submenuの二択だけであること。Item追加直後から個別画面にToggle・初期値・動作が表示され、タイプの選択肢が二択だけであること。同期は各カードに配置されること。Toggleは4種類、連続値は2種類の動作だけを追加できること。動作カード・対象行の追加削除、最後の動作削除後のメニュー項目保持。
- 動作なし・初期OFF／0では両方向に確認なしで切り替わり、名前・アイコンだけの変更でも確認しないこと。動作カードまたは初期ON／0以外の値がある場合は共通overlayを表示し、確認前のタイプ・設定を保持すること。取消・Esc・画面離脱、破棄後の全動作と初期値のリセット、名前・アイコン・登録先・素材Clipの保持、Undo／Redo、失敗時の復元とエラー表示。
- 連続値のBlendShapeで0・中間・100が両端の値へ追従すること。Clipの時間指定、生成コピーの非ループ化と素材Clip保持、Float初期値、複数動作の共有値とプロパティ競合拒否をPlay Modeで確認すること。名前・アイコン変更後も初期値・各動作の同期が保持され、円形メニューへ反映されること。
- 各動作の同期変更とUndo、全OFF時のlocalOnly、ON／OFF混在時のparameter同期とIsLocalによる本人専用動作の分離。Toggleの初期ONと連続値の初期値でも他プレイヤー側へ本人専用の変更が適用されないこと。既存の生成MA componentの引き継ぎ・Undo・非対応設定の拒否。
- Submenuの作成後にその階層へ入り、左に名前・アイコンだけを表示すること。SubmenuへItem・Submenuを追加でき、同名SubmenuでもChildren rootによって出所と追加先が特定されること。名前・アイコンの変更とUndo。
- 表示＋Material＋BlendShape＋Clipを1項目へ登録し、Play Modeで同じON/OFFへ追従すること。
- ClipのON/OFF、OFF省略時の復帰、ループ設定、初期ON/OFF、複数Clipの別プロパティ適用、競合・不正path・root表示・Legacy/Humanoidの拒否、素材Clip保持。
- Item・Submenuの追加が専用root内へまとまり、item一覧にroot・項目が表示されないこと。繰り返し追加でrootを再利用し、Submenuの親子構造・登録先・Prefab接続を維持すること。root作成・既存追加overrideの移動・項目追加をUndo／Redoでき、生成Prefabの保存でAvatar Prefabへ他のScene overrideをApplyしないこと。
- アバターrootに存在しないSkinnedMeshRendererを操作するClip、存在しないBlendShape・プロパティ、競合するClipを指定しても、Componentへのアクセス例外や画面消失を起こさず、入力参照と生成済み設定を保持して同じ編集欄にエラーを表示すること。

- 編集・動作削除・Controller再生成・項目削除・本体削除のUndo/Redo、Prefab保存後の再読み込み。
- 「メニューへ戻る」で個別編集が閉じて設定内容と元の階層・ページが保持されること。階層と2ページ目以降の戻る、サブメニューの設定、削除・型変更時の親への戻り。
- 保護された元Prefab・メニューassetと出所不明の項目で、簡易編集・詳細編集・個別入力だけが無効になること。Submenuは円形メニューと開くボタンから移動・戻る・ホバー強調でき、移動先の編集可否を個別に反映すること。参照先メニューassetが保護されていても追加・登録でき、元assetは変更されないこと。Children rootが編集不可の場合とPlay Modeでは追加・登録も無効であること。
- 8項目以下・9項目以上の分割、最終ページだけの追加、追加後の選択。短い名前・複数行の名前が下端・左右端で切れず、強調がちらつかないこと。
- Toggleと連続値で対象SkinnedMesh・BlendShape選択が同じフォームになること。Toggleの対象追加で未設定行が消えず、追加・保存・再読込できること。OFFの現在値が編集不可で、ON値の編集、対象・BlendShape変更後のOFF値表示と生成OFF Clipが一致すること。Material差し替えの変更元→変更先が1行に収まること。既存の対象・値の保持、対象行の追加・削除、未指定時の選択無効、0〜100の検証と入力復元、対象消失表示、アバター外・同名path拒否、生成Prefabのitem一覧除外。
