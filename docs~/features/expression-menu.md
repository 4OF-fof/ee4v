# Expression Menu

`src/Editor/Feature/Avatar/ExpressionMenu`の`Ee4v.ExpressionMenu.Editor`は、Unity 2022.3 / VRChatでギミック制作とExpression Menu編集を扱います。AssetManagerの「Expression Menu」カテゴリと単独の`ee4v/Window/Avatar/Expression Menu`が同じ`ExpressionMenuView`を使用します。個別編集の下部操作はAvatarEvaluationのプレビューへ接続し、MA Merge Armature・Bone Proxyを反映した再生とNDMF Preview対応の加工を表示します。実行時の動作確認はPlay Modeの既存GestureManager Controlsで行います。

## ギミックエディター

左ペイン最上部の中央に置いた「ツリー」「ExMenu」の二択タブで、階層ツリーと円形のExMenu表示を切り替えます。パーツ／マテリアルのタブと同じ角丸の外枠・36pxのボタン・選択色を使用し、現在の形式に対応するタブを常に一つ選択します。選択済みのタブを押しても表示を解除せず、選択と編集を維持します。右側の編集欄と選択中の階層・項目は両表示で共有します。ツリーはRoot・Submenu・通常項目を表示し、展開ボタン・インデント・親子の罫線に、項目アイコン・種類・削除操作を組み合わせます。空のメニューにも、その階層へ登録する追加行を表示します。

展開した各Root／Submenuの子項目の末尾へ、インデント・アイコン・ホバーを項目行に揃えた追加行を置きます。Item／Submenuの二択でその階層へ登録し、右の選択先が別階層でも登録先を変えません。空のメニューも展開でき、追加行は登録済み項目と並び替えの対象に含めません。ツリーは円形メニューのページ分割によらず、展開した階層の全項目を表示します。各項目行はハンドル、展開ボタンまたは同幅の余白、28pxのアイコン、名前、種類、削除のFluentアイコンで構成し、選択行全体を共通色で強調します。読取専用の通常項目も右で閲覧でき、入力・ハンドル・削除だけを既存許可で無効にします。Submenuは保護状態にかかわらず開けます。Rootは20pxのフォルダーアイコンを28pxの領域へ揃え、移動・削除を持ちません。Rootの編集許可は表示元とホストの書き込み可否で判断し、追加と既存項目の編集は別の許可として扱います。

左上に機能名の「Expression Menu」見出しは配置しません。Rootと項目のアイコン領域・名前の開始位置を揃えます。

ツリーの「読取専用」ラベルは行のリンクボタン内の右端に配置し、選択・ホバーの背景へ収めます。名前が長い場合は名前だけを省略し、ラベルの幅を保持します。ラベル上からも行のクリック・階層移動を行えます。

ツリーのRoot／Submenuから編集対象の階層を選択します。chevronは子項目の表示だけを開閉し、右側の選択を変えません。初期状態はRootを展開し、選択が変わったときだけその祖先を自動展開して行を表示範囲へ収めます。同じ項目の再描画で閉じた枝を開き直しません。開閉状態は同じ表示元で保持し、表示元変更時に初期化します。表示形式の二択タブをスクロール領域の上へ固定し、ツリー全体を一つのスクロール領域として扱います。同じ参照は各pathへ表示し、循環参照は祖先の再展開を止めます。

ハンドルと項目名を6px以上ドラッグすると移動を開始します。ハンドルは押下時にポインターを捕捉し、ハンドルの外へ素早く動かしてもドラッグを開始します。RootとSubmenuの行本体へのドロップはその階層の末尾への移動、通常項目の上下半分と同じ親のSubmenuの上下8pxは並び替えに使用します。別階層からの移動はSubmenuの行全体を対象にします。行間は並び替えだけを判定し、追加行はドロップ先にしません。移動可能な閉じたSubmenuの行本体へ600ms留まると選択を変えずに展開し、ドラッグを続けて子階層へ移せます。離脱・無効な場所・取消・画面終了では展開待ちを破棄します。ドラッグ中の項目名はコレクションと同じUnity標準のドラッグ表示を使用し、有効な階層の移動先をfocus色、無効な行をerror色で示します。保護・出所不明・満杯の移動先、自身・子孫への移動と、保護項目・異なる出所を越える並び替えを拒否します。Rootはドラッグできません。上下端の自動スクロールは内容とviewportのlayout高から範囲を求め、0〜末尾へ制限します。表示内に収まる場合はスクロールせず、先頭・末尾へ達したら止めます。ツリーのScrollViewはClampedを使用し、負のoffsetや範囲外への伸長を許可しません。Esc・範囲外へのドロップ・ドラッグ終了・画面離脱の取消と、Relocate／MoveのUndo・保存契約を維持します。各行の移動操作はその項目の実際の親階層を移動元として判定します。

ツリーの行は最小48pxとし、長い名前を省略してtooltipへ階層pathを含む全文を表示します。削除は28pxのアイコンボタンとtooltipで示します。階層間の移動はハンドルからのドラッグで行います。左右は独立して縦スクロールし、同じアバター・表示元で左の位置を保持します。選択変更では対象行を表示範囲へ収めます。同じ項目のフォーム更新は右の位置も保持し、別項目・階層では右だけを先頭へ戻します。

`ExpressionMenuView`の右ペインは統合画面460px（最小420px）、単独Window380px（最小300px）とし、他カテゴリと同じ区切り線・背景・16pxの内余白を使用します。選択がない場合は現在のRootまたはSubmenuの名前・アイコンを表示し、Submenuだけを既存許可で編集します。「ExMenu」を選ぶと円形メニューへ切り替え、既存のページ移動・選択・追加を使用します。ツリーで選んだ項目の円形ページを合わせ、「ツリー」を選ぶと現在の階層・項目をツリーへ反映します。「動作を確認」は左ペイン全体を選択項目のアバタープレビューへ切り替え、右のフォームを維持します。確認中はツリー・ExMenu・表示形式のタブ・編集元の選択欄を表示せず、戻る操作と動作の操作ボタンをプレビュー内へ配置します。プレビューの戻るボタンは確認を閉じ、直前の表示形式・階層・選択・開閉・一覧の位置へ戻します。AvatarEvaluation、NDMF Proxy、Prefab表示用コピー、カメラと仮ポーズ、離脱時の描画資源の破棄は既存契約を維持します。横幅880px未満は一覧と編集欄を縦に積み、入力を隠しません。名前・アイコンの変更は型、parameter、初期値、同期設定や動作を変更しません。 Toggleの「初期状態をONにする」は、GestureManagerと同じ`BSX_GM_Running_Param`の50px画像を主アイコンへ重ね、同じ2度ずつの回転で表示します。操作タイプの補助アイコンと扇形の通常色は維持し、tooltipにも初期ONを示します。初期OFFへ戻すと回転表示を除去し、表示切り替え・再描画・画面離脱では回転アニメーションを停止・破棄します。設定変更の成功後に表示を更新し、Undo／Redoでも初期状態の表示を再取得します。

右側フォームでは64pxのアイコンの右へ名前・タイプ・初期値を並べ、動作カードを下へ配置します。「項目の設定」はその節に入力・編集元・案内などの要素がある場合だけ表示し、追加要素がないee4v項目では見出しも除去します。Texture選択とアイコンドラッグ、透過Textureのalpha、未設定時のGameObject代替アイコンは既存のままです。操作タイプはtooltipで示し、説明文・空状態の案内文は追加しません。同期は各動作カードにある既存設定を使用します。通常項目の既存フォームとSubmenuの名前・アイコン編集は同じ右ペインで扱います。統合画面は専用ExpressionMenuHostを使用し、単独Windowの最小幅は800pxです。生成・保存・同期・repo外のデータ契約は変更しません。

一覧と円形メニューの追加はItem／Submenuの二択です。Itemは初期Toggle・動作が空の専用Prefabを現在の階層へ登録して右に選択します。タイプはToggle・0〜100・Button・Puppetの4種類で、Puppet内で2 Axis／4 Axisを選びます。「動作を追加」は動作セクションの見出しに置き、対応する動作だけを列挙します。同じ種類を複数追加でき、カード右上のFluent Dismissでその動作だけを除去します。tooltipに削除範囲を示し、最後の動作を除去しても項目を保持します。項目自体の削除は左の一覧に置き、右の編集欄へは置きません。全動作は1つのMenu Itemに属し、Puppetでは各動作に軸を指定します。

動作カードの見出しと設定を区切り線で分け、複数対象を持つ動作は設定ごとの内枠へまとめます。内枠の見出しにはオブジェクト・BlendShape・マテリアル差し替え・マテリアルのパラメーター・Transform・Componentの種類と1始まりの番号を表示します。内枠の右上のFluent UI Dismiss（×）ボタンはその枠内の設定だけを除去し、tooltipに対象の見出しと削除範囲を示します。アバターのObjectやアセットは削除しません。カード末尾には＋アイコン付きの全幅ボタンで「オブジェクト設定を追加」「BlendShape設定を追加」「マテリアル差し替え設定を追加」など種類ごとの追加操作を配置します。tooltipで対象・値、または変更元・変更先の空の設定欄を1組追加することを示します。追加・削除は各動作の既存のUndo・保存・編集許可を使用します。

| 操作タイプ | 利用可能な動作 | 初期状態 |
| --- | --- | --- |
| Toggle（ON／OFF） | オブジェクト表示／非表示、マテリアル差し替え、BlendShape変更、パラメータの値を変更、マテリアルのパラメーター変更、Transform変更、Componentの有効切り替え | ON／OFF |
| 0〜100（連続値） | BlendShape変更、パラメータの値を変更、マテリアルのパラメーター変更、Transform変更 | 0〜100の数値 |
| Button（実行） | パラメータの値を変更（Trigger実行、Bool／Int／FloatのSet） | OFF固定、値保存なし |
| Puppet（軸操作） | Transform変更 | 各軸0、中心位置 |

Puppetの新規動作はTransform変更だけを提供します。ほかの保存済み動作カードも表示・編集・削除できます。Buttonの候補とカード名は他のタイプと共通の「パラメータの値を変更」を使用します。

ButtonはSDKのButton controlを使用し、クリック時の一時的なONとSDKによるOFFへの復帰で動作します。初期値の入力は配置しません。Puppetの2 Axisは左右・上下の−1〜1、4 Axisは上・右・下・左の0〜1を使用し、各動作の軸選択と範囲へ反映します。左右・上下では範囲の左端が−100、右端が100に対応し、中心は両端の中間値になります。4 Axisの左端は0、右端は100です。Puppetにも初期値の入力は配置しません。軸parameterは固有の共通IDへ軸名を付けて生成し、各軸を使用する同期ONの動作がある場合だけ同期します。タイプや軸数の変更でも共通IDを保持し、不要になった生成軸parameter宣言を除去します。

他プレイヤーへの同期は動作カードごとに設定します。ONの動作は他プレイヤーにも適用し、OFFの動作は本人だけに適用します。同じItemに両者を組み合わせられます。動作の新規追加時は同期ONです。既存のMA ReactiveComponentやClip動作がある項目はToggleとして扱います。

操作タイプとPuppetの軸数の切り替えは、破棄対象がある場合に表情のジェスチャー割り当てと同じ共通`ConfirmationOverlay`で確認します。中立色の本文と区切り線のある操作欄を使用し、赤い「破棄して変更」を左端、通常の「編集を続ける」を右端へ配置します。動作カード・生成MA ReactiveComponentがなく、現在の初期状態がOFF／0の場合は確認せず即時に切り替えます。名前・アイコンだけの編集では確認しません。追加済みの空の動作カードも破棄対象とします。確認中はタイプと軸数の表示、保存データを元のまま保持し、背後のWindowを操作できません。「破棄して変更」で初期状態をOFF／0へ戻し、すべての動作カード・対象・Clip参照・動作ごとの同期設定と生成MA ReactiveComponentを除去して、新しい型のparameter・Controllerを構成します。名前・アイコン・メニュー登録先・固有parameter IDと素材Clipは保持します。値保存はButtonでは無効、他のタイプでは有効です。「編集を続ける」またはEscは変更せず閉じます。画面を離れた場合も確認を取り消します。失敗した場合はUndo transactionで元へ戻し、overlay内にエラーを表示して元のタイプに留まります。確定した変更はUndo／Redoの対象です。

右ペインの編集は選択項目の出所MA Menu Itemを参照します。Toggleの「初期状態をONにする」と連続値の「初期値（0〜100）」は全動作共通です。名前・アイコン・タイプを更新しても選択を維持し、一覧と表示中の円形メニューへ反映します。メニュー未登録で保持する操作は設けません。

画面表示・選択・再描画だけでは既存データを変更しません。メニュー未登録の項目は編集元候補へ含めません。一覧から項目を削除した場合は既存処理でギミックのScene上のGameObjectと付属componentをUndoで除去し、選択を解除して現在の階層の設定を右へ表示します。保存済みassetは保持します。既存MA項目も既存フォームで扱い、動作の追加・削除はee4v生成Prefabだけに許可します。

操作はプレビュー画像内の下部中央へ重ね、正面・背面切り替えと同じ背景・枠・角丸を使用します。Toggleでは左にON・右にOFFを配置し、選択状態を強調する2ボタン、0〜100ではスライダーと32px幅の数値入力、Buttonでは外側の枠だけを持つ実行ボタンを表示します。Puppetの2 Axis・4 Axisは共通の2D入力パッドを使用し、中心と現在位置の点を表示します。2 Axisは設定した動作の入力方向だけを有効にし、未使用の左右または上下を0へ固定します。左右だけなら横方向、上下だけなら縦方向の1軸に制限し、両方の入力を使用する動作がある場合は両方向を有効にします。動作未設定時は左右方向だけを使用します。ガイド線も有効な方向だけに表示します。クリック・ドラッグ位置を各軸−1〜1へ変換し、領域外では端へ制限します。矢印キーの組み合わせでも方向を操作できます。4 Axisはパッドの左右・上下の符号から上・右・下・左の0〜1を計算し、斜めでは対応する2方向の連続値を同時に入力します。パッドは押している間だけ有効になり、ポインターを離す・キャプチャを失う・フォーカスを失うと中心へ戻ります。2 Axisは左右・上下の−1〜1、4 Axisは上・右・下・左の0〜1へ変換し、反対方向を同時に押した場合は相殺します。初期表示は保存済みの初期ON／OFF・初期数値、Puppetの中心値を使用します。操作値は表示中だけ保持し、項目の初期値・recipe・Prefab・Scene・Undoへ書き込みません。フォーム更新と画面離脱で操作値を初期化します。

一時Clipと操作値は`PrefabScenePreview.SetAnimationSampler`からAvatarEvaluationへ渡します。複数Clipは`AvatarAnimationFrame.Sample`で評価し、Puppetの直接Transform変更は`ResolveTransform`で参照先を取得します。Merge Armature・Bone ProxyとClipのpath変更は共通プレビューが所有します。表示切り替え・Material・BlendShape・Transform・対応Componentの値を再生用コピーで評価し、Scene入力ではNDMF Preview対応Pluginの加工後Rendererへ表示値を反映します。Prefabアセット入力では表示用コピーへ描画中だけ適用して復元します。パラメーター動作は計算した出力値や実行したTrigger名を下部へ表示し、外部Animatorの遷移やPhysBoneなどの実行時シミュレーションはPlay Modeで確認します。ClipとrecipeはExpression Menu、再生用Scene・Clipの参照先変更・MaterialコピーはAvatarEvaluationが所有し、メモリ内だけに保持して離脱時に破棄します。出所MA Menu ItemのないSDK asset項目は操作を無効にし、tooltipでPlay Modeの確認先を示します。

サンプリング用の一時Clipは、メモリ内のコピーだけをLegacy方式へ切り替えます。`SampleAnimation`によるHumanoid Animatorの再bindと、Clipで指定していない骨格の位置・回転・スケールの初期化を防ぎ、仮ポーズとMA衣装の追従を保持します。仮ポーズの腕の補正はサンプリング済みの姿勢ではなく、基準骨格と更新済みの表示用回転から上腕・前腕の順に計算します。空のClipも骨格を変更しません。入力Clipと保存・ビルド用Clipは変更せず、入力時のLegacy／Humanoid Clipの拒否も維持します。

## ItemとSubmenuの作成

Item・Submenuとも現在の階層へ追加し、出所componentで登録先を特定します。Itemは一覧を維持して右の編集欄へ選択します。SubmenuはMA Children構成で作成し、その階層へ移動して名前・アイコンを右に表示します。そこから再びItem／Submenuを追加できます。生成Submenuへparameter・同期・既定値・型切り替えなどの動作用設定は表示しません。

専用PrefabはMA Menu Itemを使用します。ItemはToggle、空の動作設定で作成します。保存用ControlはToggle、固有パラメーター名、値1、同期・値保存あり、初期OFFです。タイプ選択でToggle・RadialPuppet・Button・TwoAxisPuppet・FourAxisPuppetへ更新します。初期状態の編集はToggleとRadialPuppetに配置します。SubmenuはSubMenu型、空parameter、値0、同期・値保存・既定項目なしで作成します。`MenuSource`はChildrenにします。動作テンプレートの選択はItemの「動作を追加」だけに配置します。

Toggleの表示／非表示・マテリアル差し替え・BlendShape変更はEditor専用recipeの`MenuReactiveAction`へ保持し、カードごとのON/OFF ClipとFXレイヤーを生成します。Object Toggleは対象とON時の表示、Material Swapは変更前後のMaterial、Shape Changerは対象SkinnedMesh・BlendShape・ON時の値（0〜100）を編集します。いずれも対象行を追加・削除できます。対象行の編集は全体の初期ON/OFFを変更しません。Material Swapは変更元と変更先のObjectFieldを矢印で結び、見出し付きの2列を1行に配置します。新規Material Swapはアバター全体を対象とし、指定した元Materialを使用する各Rendererのslotへ変更先を割り当てます。OFFは設定時の値へ戻します。

既存のMA ReactiveComponentは最寄りのMenu Itemに属するものだけをフォームへ表示します。ee4v生成項目でrecipeを変更すると、既存の対象・値・反転と同期設定をrecipeへ引き継ぎ、元componentをUndo付きで除去します。描画だけでは変換しません。Quick SwapとBlendShape削除は変換を拒否し、元の設定を保持します。既存の外部MA項目はcomponentの設定編集を維持し、動作単位の同期変更と動作カードの追加・削除は許可しません。

全動作はメニューの共通BoolまたはFloat、Puppetでは指定した軸のFloatを参照します。同期ONの動作が1つ以上あるときだけ対応する入力parameterを同期し、すべてOFFならローカルparameterとして構成します。同期OFFの動作レイヤーはmotionを持たないLocalOnly stateを既定とし、組み込みBool `IsLocal`がtrueのときだけ動作stateへ遷移します。他プレイヤー側ではそのレイヤーからプロパティを書き込みません。初期ONや連続値の初期値がある場合も同じ条件を適用します。入力parameterとカードごとの同期フラグ・レイヤー制御により、同期動作と本人専用動作を1つのメニューで操作します。

連続値のBlendShape変更は、対象SkinnedMesh・BlendShapeと「範囲」を指定します。「範囲」は2つの数値入力を区切り記号とともに1行へ並べ、左を操作値0、右を操作値100でのBlendShape値として扱います。Puppetの2 Axisだけは左を−100として扱います。各入力のtooltipで両端の意味を示します。複数の対象行を追加・削除でき、両端の値は0〜100で検証します。逆方向の範囲も指定できます。0〜100タイプは1秒の線形Clipを共通Floatでサンプルします。Puppetは両端の固定値Clipを指定軸の1D BlendTreeで補間し、2 Axisでは−1／1、4 Axisでは0／1をthresholdにします。連続値では表示切り替えとMaterial差し替えのテンプレートを表示しません。動作カードに常設の説明文は表示しません。

対象未指定の行を保存・再読込した場合や、指定pathにSkinnedMeshRendererが存在しない場合も編集欄を保持します。Unityのmissing-component参照は実際のnullへ正規化し、meshへアクセスせず対象の再指定・行削除を行えるようにします。

MA対象は編集中アバター内部に限定し、rootの無効化を拒否します。対象をroot相対pathのAvatarObjectReferenceへ変換し、同名の兄弟Objectと名前に`/`を含むObjectを拒否します。対象の削除・改名、存在しないBlendShapeはエラー表示します。

## マテリアルのパラメーター変更

Toggleと0〜100タイプで追加できます。カードごとの同期と複数の対象行を持つEditor専用recipeの `MenuMaterialValueAction` として保持します。各行はアバター内のRendererとMaterialの設定項目を選びます。ShaderのFloat／Range／Integer・Color（HDRを含む）・Vector・Texture、Textureの倍率／オフセット、Shaderキーワード、Shader、Render Queue、GPU Instancing、Double Sided GI、Global Illumination Flagsを列挙します。非表示のShaderプロパティも含めます。TextureのNoScaleOffset指定は尊重します。使用Materialにある設定を列挙し、Shaderの項目は表示名と内部名を併記します。同じObjectに複数のRendererがある場合、先頭のRendererだけを対象にできます。

Toggleは現在値のOFFと編集するONを2列に並べます。OFFは編集不可です。値の型に合わせて数値・整数・チェック・Color・成分ごとの入力・Texture／Shader参照を表示します。0〜100タイプはUnityのRenderer animation bindingが提供する項目だけを候補にし、両端の値を入力して1秒の線形Clipで補間します。対応する数値・Color・Vector・Texture倍率／オフセットを使用できます。負の値と逆方向の範囲を使用でき、非有限値・整数項目の小数を拒否します。ShaderのRange属性は入力範囲として強制しません。

アニメーション対応項目はRendererの `material.<property>` を操作します。同じ名前の項目を持つ複数のMaterial slotに共通の値を適用し、OFFはUnityのbindingから取得した現在値（通常は先頭Materialの値）へ戻します。slot別の数値復帰は提供しません。アニメーションできない項目はToggle専用で、MaterialのコピーへON設定を適用し、Rendererの該当slotの参照を切り替えます。Cull・ZWrite・Blend・Stencil等のrender stateもコピーで扱います。一般的なプロパティ名とShaderの依存ソース内のShaderLab命令から対象を識別し、連続値の候補から除外します。同じカード内のTexture・キーワード等の変更はslotごとに1つのコピーへまとめます。OFFは各slotの元Material参照へ復帰します。生成MaterialはControllerのsubassetとして保存し、元Material assetは変更しません。

対象未指定の行を保持して生成から除外します。Renderer・項目の変更時は両端と参照を現在値で初期化します。描画だけでは保存値を変更しません。Textureのdimension、Render Queue（−1〜5000）、GI flags（0〜7）、チェック（0／1）、非有限値、対象消失、アバター外・曖昧なpathと同一bindingの競合を検証します。Materialの差し替えが同じslotと競合する場合も拒否します。不正な編集は元へ戻して入力欄とエラーを表示し、再指定・行削除を行えます。同期・Undo／Redo・保存・タイプ変更時の破棄には他の動作と同じ契約を使用します。ButtonとPuppetの候補には含めません。

## Transform変更

Toggle・0〜100・Puppetで追加できます。 `MenuTransformAction` のカードに複数の対象Objectを保持し、各対象で位置・回転・サイズの操作を個別に有効にできます。値はlocalPosition・localEulerAngles（度）・localScaleを使用します。対象変更時は両端を現在値で初期化します。Toggleは編集不可の現在値OFFと編集するON、0〜100は両端のXYZ入力を並べます。0〜100は各成分を線形に補間します。未設定の行・全操作OFFの行を保持します。

Puppetの2 Axisは入力方向を左右／上下から選び、XYZの1軸を割り当てます。4 Axisは左右と上下へ異なるXYZの2軸を割り当てます。左右はRight／Left、上下はUp／Downの値から操作し、同じ軸を選んだ際はもう一方の割り当てを入れ替えて重複を防ぎます。位置・回転・サイズで共通の軸割り当てを使用し、各操作の選択軸の両端だけを編集します。中心は両端の中間値、未選択のXYZ成分は設定時の現在値です。2 Axisは−1／0／1の1D BlendTree、4 Axisは四方向parameterを使用する入れ子の1D BlendTreeと9つの姿勢Clipで補間します。回転の補間にはUnityのBlendTreeの回転補間を使用します。2 Axisは選択した入力だけ、4 Axisは四方向すべてに動作の同期フラグを反映します。

非有限値・消失した対象・アバター外・曖昧なpath・不正な軸指定・他の動作との同一binding競合を拒否します。QuaternionとEulerの別表現による回転競合も検証します。FXレイヤーとClipを生成し、ToggleのOFF復帰、同期のLocalOnly gate、Undo／Redo・保存・タイプ変更時の破棄には他の動作と同じ契約を使用します。Buttonには提供しません。

## Componentの有効切り替え

Toggleで追加できます。 `MenuComponentAction` の各行で対象ObjectとComponent、ON時の有効状態を設定します。OFFは現在の `m_Enabled` 値を示す編集不可のチェックで、復帰Clipも現在値を取得します。Renderer・Collider・Animator・Light・Camera・AudioSource・Cloth・Animation・Unity Constraintと対応するVRC Dynamics／Spatial Audio／HeadChop／Station componentのうち、Unityが `m_Enabled` のanimation bindingを提供するものを候補にします。対象Objectに同型Componentが複数ある場合は識別できないため、その型を候補から除外します。MA・ee4v・Descriptor、アバターDescriptorと同じObjectのAnimatorは候補に含めません。

複数の対象行と動作ごとの同期を設定でき、未指定行を保持します。対象消失・非対応のComponent・同一binding競合は編集を拒否して復元し、再指定・行削除を行えるカードを保持します。FX生成・OFF復帰・Undo／Redo・保存・タイプ変更時の破棄には他の動作と同じ契約を使用します。

## パラメータの値を変更

動作カードでパラメータ名を設定します。ToggleはBool、連続値・保存済みPuppet動作はFloat／Intを使用し、型の選択欄を配置しません。ButtonだけはTrigger・Bool・Int・Floatの型を扱います。名前は直接入力でき、Playable Layer、MA Merge Animator、Expression Parameters、公開MA Parametersから型付きの候補を選択できます。既知の名前は型を自動反映し、Buttonの型選択欄を無効にします。未知の名前は数値操作ではFloat、Buttonでは初期Triggerとし、Buttonの型を選択できます。TriggerでExpression Parametersに同名宣言があるものは候補から除きます。MAのprivate・prefix定義、自分自身の入力parameterは候補へ含めません。Toggleは「設定する値」の下に「メニューOFF時」「メニューON時」の見出しを配置し、それぞれFalse／Trueを選択します。連続値は両端の範囲を1行で編集します。ButtonのTriggerは値の入力を設けず、Boolはチェック、Intは整数、Floatは小数の「設定する値」を1つ表示します。型を変更すると値を初期化します。対象未指定のカードは保持し、動作レイヤーへ含めません。

設定はEditor専用recipeの`MenuParameterAction`へ保持します。ToggleはFXレイヤーのOFF／ON stateの`VRCAvatarParameterDriver`でSetし、初期状態も適用します。Buttonはメニュー入力用BoolをSDKのButtonで操作し、ONへ入ったときだけDriverのSetで対象Triggerを実行するか、Bool／Int／Floatを指定値に設定します。OFF・初期状態にはDriverを配置せず、起動時の誤実行を防ぎ、Buttonの復帰後も設定した値を保持します。対象TriggerはAnimator Controllerだけに宣言し、Expression Parameters／MA Parametersには追加しません。同期は入力Boolと各プレイヤー側の実行で扱います。連続値・Puppetは2つのstateを各0.02秒以上保持して交互に遷移し、stateへ入るたびにCopy／Convert Rangeで入力Floatを指定範囲へ写します。Puppetは動作が指定した軸をsourceとし、2 Axisでは−1〜1、4 Axisでは0〜1を使用します。止めた操作値も継続して適用し、逆方向の範囲も使用できます。Intの中間値はSDKの切り捨てを使用します。時計用Clipは共通parameter IDに`/CopyClock`を付けた内部Floatだけを操作します。

カードの同期設定は共通parameterの同期判定とIsLocal gate・DriverのlocalOnlyへ反映します。対象parameterの既存のExpression Parameters／MA Parametersの同期・保存宣言は変更しません。生成Controllerの対象parameterは既存Controller・Expression Parameters・明示的なMA Parametersの初期値を引き継ぎ、Buttonを押す前の値を維持します。既存宣言で同期されている対象の値は、その宣言に従って同期されます。新しい対象名は生成FX Controllerだけへ型を宣言し、同期ONの場合は共通parameterから各プレイヤー側のDriverで適用します。

組み込みparameter、自分自身の共通parameter・時計parameter、同じItem内の重複した対象名、メニューの型と一致しない既存parameterを拒否します。非有限値、Boolの0／1以外、Intの小数を拒否し、Expression Parametersで宣言されたIntは0〜255・Floatは−1〜1も検証します。不正な編集はUndo transactionで元に戻し、入力と動作カードを再表示してエラーを示します。削除・型切り替え・保存・Undo／Redoは他の動作と同じ契約を使用します。

## 登録済みのClip動作

Animation Clipは新規追加のテンプレートへ含めません。登録済みのClipカードは引き続き表示・編集・削除できます。アバターroot相対の通常ClipをON/OFFで指定し、プロパティ操作・エフェクトなどを同じメニューで切り替えます。OFF省略時はONが操作するプロパティについて設定時のアバターの値を取得し、復帰用Clipを生成します。ON/OFFの片方だけにあるプロパティも、もう片方に設定時の値を補います。素材Clipは変更しません。ON未指定のカードはControllerへ含めません。

設定は専用Prefabと同じフォルダのEditor専用`Gimmick.asset`へ保持し、空のギミックの識別にも使用します。`Gimmick.controller`へカードごとのFXレイヤー、ON/OFF stateとClipのコピーを生成します。共通Boolパラメーターで即時遷移し、Write DefaultsはOFF、レイヤーweightは1です。MA Merge AnimatorをAbsolute path / FX / Appendで接続します。初期ON/OFF変更はControllerのparameter defaultと初期stateにも反映します。有効なClip・parameter動作がすべてなくなると生成Merge Animatorを除去します。

連続値ではON用Clipだけを指定し、操作値0で先頭、100で末尾をサンプルします。生成コピーのloopTimeを無効にし、FXレイヤーの単一Value stateへmotion time parameterとspeed 0を設定します。素材Clipは変更せず、OFF用参照は保持したままフォームから隠します。時間経過での再生は行いません。生成ControllerのFloat defaultは初期値を100で割った値です。RadialPuppetの主parameterは空とし、subParametersの先頭へ固有パラメーターを設定します。同じGameObjectへMA Parametersを配置してFloat・明示的default・値保存・localOnly（同期設定の反転）を指定します。動作が未設定でもこのparameter設定は保持します。Toggleへ戻すと生成したFloat設定を除去します。

Legacy／Humanoid Clip、解決できない対象・プロパティ、アバターrootの表示操作、同名pathを拒否します。生成する全動作カード間で同じプロパティを操作することも拒否します。外部Clip変更後はカードでClipを再指定して生成物を更新します。動作確認はPlay Modeで行います。

Clip入力時は、変更の確定とUndo記録の前に、対象Object・Component・BlendShape・プロパティの存在と全動作間の競合、復帰用Clipの生成を検証します。存在しないComponentへAnimationUtilityでアクセスしません。不適合なClipは入力欄を元の参照へ戻し、同じ編集欄にエラーを表示します。対象を解決できない場合はClip名・対象path・Component型・プロパティを添えます。保存済みrecipe・Controller・Prefabと選択中のメニュー、動作カードを保持します。

## BlendShapeの選択

Toggleと連続値は共通の対象選択フォームを使用します。対象行ごとにSkinnedMeshRendererのObjectFieldと、そのmeshのBlendShape名を列挙するドロップダウンを縦に配置します。対象未指定時はBlendShapeの選択を無効にし、Renderer変更時は最初のBlendShapeを選択します。Toggleはその下に「OFF → ON」の2つの数値欄を1行で表示します。OFFは選択したRendererの現在のBlendShape値を読み取る編集不可の欄で、対象とBlendShapeの選択後に更新します。OFF値はrecipeへ保存せず、生成Clipの復帰値も設定時の現在値から取得します。ONだけを0〜100で編集します。連続値は2つの値を1行にした範囲入力を表示します。「BlendShape設定を追加」と各内枠右上の×ボタンで複数の対象行を編集し、対象とBlendShapeが未指定の行も保持します。未設定の行はClip生成から除外し、指定後に動作へ反映します。既存の対象と値は描画だけでは変更しません。指定済みの対象やBlendShapeが消失した場合はエラーを表示し、再指定と行削除を行えます。不正な値や更新失敗時は入力欄を元に戻します。

## 並び替え

階層間の移動はツリーへのドラッグで確定し、RootとSubmenuの行本体を移動先にします。現在の階層、自分自身・子孫、保護された編集元、8項目に達した移動先へのドロップは拒否します。assetのControlは移動先assetの末尾へ移し、MA Childrenへ移す場合は同じControlを持つ専用MA Menu Item Prefabへ変換します。専用生成MA項目は同じPrefabを使用して移動先へ再配置し、Childrenでは自身のInstallerを外し、assetまたはRootではInstallerの登録先を変更します。名前・アイコン・parameter・動作・子メニューを保持します。階層とInstallerの変更はアバターのPrefab overrideとして保持し、ホストのアバター保存で確定します。移動中に生成親Prefabへ階層変更をApplyせず、Sceneと保存元の構造変更を二重にUndoへ記録しません。通常SceneのMA項目と追加GameObject overrideも移動できます。既存Prefabに組み込まれた非生成MA項目と、Menu assetを併用するInstallerは階層構造を変更できないため対象外です。移動は1回のUndo／Redoで戻せ、失敗時はSceneと変更した保存元を復元します。

一覧の「削除」はItem・空のSubmenuを含め、対象名を示す共通の警告overlayで確認してから実行します。Itemと空のSubmenuは「削除」、中に項目があるSubmenuは内容も消える説明と「中身ごと削除」を表示し、「キャンセル」で閉じられます。取消とEscでは設定を保持します。assetのSubmenuは親Controlの登録を除去し、共有される参照先asset自体は削除しません。生成MA項目は配下のGameObjectを含めて除去し、生成親Prefabを保存します。通常MA項目はMenu Item componentの登録を除去します。

各項目行にFluent UIの6点グリップを配置し、項目名からも既存のツリードラッグを使用できます。同じメニューassetのControl間と同じ親を持つMA Menu Item間で順番を変更できます。ホバー背景は行全体へ共通のsurface-hoverを一枚だけ描画し、名前・ハンドル・開閉・削除・追加ボタンの背景と通常枠線は透明に揃えます。削除もGhostボタンを使用し、選択・ドロップ先の色はホバー中も維持します。名前ボタンは通常・ホバー・押下・フォーカスで背景画像を描画せず、背景色と枠線を透明にし、クリック・選択の背景と名前のキーボードフォーカス枠は行全体へ一度だけ描画します。ツリーのボタンの状態指定は`UiButton`のclassへ適用し、基底`Button`の型セレクターには依存しません。ハンドル・開閉・追加のキーボードフォーカスには共通のfocus枠線を使用します。削除ボタンは通常・ホバー・押下・フォーカスで枠線と背景を描画せず、アイコンだけを表示します。ドラッグ表示はUnity標準へ揃え、有効な挿入位置は行間の中央に一本の線を重ねて示します。行の枠線や高さは変更せず、上の行の下端と下の行の上端を同じ挿入境界として扱います。展開中のSubmenuの後ろへ挿入する場合は子の領域を含めた下端で判定します。Esc・範囲外へのドロップ・ドラッグ終了・画面離脱は変更せず取り消します。ハンドルの上下矢印キーは同じ親の隣へ並び替え、項目名にフォーカスした矢印キーでは並び替えません。円形メニューのページ境界によらず、既存の移動・Undo・保存処理を使用し、名前・アイコン・parameter・動作を維持します。

保護・出所不明の項目、異なるメニューassetやassetとMA間、異なる親を持つMA間の移動は無効です。移動元から移動先までの全項目も確認し、保護された項目や保存元の境界を飛び越える移動を拒否します。MAでは親Transformと両項目の編集可否も確認します。assetはControl配列の順番を保存し、MAは兄弟順を変更します。生成Prefab内では対応する元Prefabの兄弟順だけも保存し、アバターの他のoverrideは適用しません。順番の変更はUndo／Redoに対応します。

## 表示と出所

統合画面と単独Windowは同じ一覧・編集欄を使用します。3Dプレビューは「動作を確認」で必要時だけ開きます。統合画面は合成表示に固定し、単独Windowだけに表示・編集元の選択欄を置きます。説明用HintBox、再読み込み・メニューasset保存ボタンは配置しません。編集エラーと読み取り専用の案内は必要時に表示します。

メニューの読み取り結果は表示中のView内で保持し、Submenuを開く・戻る・ページ移動・ツリーからの階層移動・個別編集との往復・表示元選択では再利用します。編集・追加・削除・コピー差し替え・項目の移動後は再解決します。対象アバターと参照メニューのプロパティ変更、Hierarchy・Projectの変更、Undo／Redo、Viewの再接続で無効化し、次の画面更新時に再取得します。対象アバターが変わった場合も再取得します。変更通知の購読はViewの表示中だけ維持し、離脱時に解除します。読み取り専用メニューのコピー可否調査も同じ読み取り結果の期間で共有し、アバター内のserialized参照を項目や階層ごとに再走査しません。実際のコピー操作では最新の参照と編集許可を再検証します。

ツリーへのドラッグは同じ移動先への可否判定をドラッグ中だけ再利用し、メニューの変更通知があれば破棄します。同じ移動先では強調classを維持し、展開後は新しい行の移動可否を確認します。ドロップの確定時は既存の編集許可・移動可否・出所を再検証してから保存します。

初期表示はDescriptorへMA Menu Installer、Menu Item、Menu Group、Menu Install Targetを解決した構成です。円形メニューはGestureManagerの`GmgCircleElement`、`RadialMenuUtility`、`RadialCursor`を使用し、300pxの円、100pxの中央円、50pxのアイコン、扇形のグラデーション・区切り線・設定色・カーソルを描画します。root初期ページには項目と追加またはNextを表示します。階層内と2ページ目以降は「戻る」を先頭へ配置します。時計回りに項目、末尾操作の順で均等に分割します。

階層移動・ツリーの展開・カードの「開く」はControlTypeがSubMenuの項目だけへ提供します。Toggleなどに残る未使用のサブメニュー参照はCoreの読み取り時に無視し、通常Itemとして個別編集を開きます。元メニューassetの参照は消去しません。

8項目超の合成メニューは7項目とNextへ分割します。Nextがあるページの末尾はNextだけ、最後のページだけに「＋／追加」を配置します。簡易編集行も現在のページの項目だけを表示します。追加後は該当項目のページを保持して個別編集を開きます。追加・戻る・Nextはassetの8項目上限に含めません。ページ移動は表示だけで元assetを分割しません。

保護・読み取り専用・出所不明の項目は名前・アイコンの入力と編集・移動・削除を無効にします。円形プレビューでも編集だけを行うItemは文字・主アイコン・型の補助アイコン・扇形をグレーアウトします。Submenuは保護状態にかかわらず円形メニューと「開く」から移動でき、ホバー強調も有効です。ツリーのハンドルと削除ボタンは編集不可の場合に無効表示します。移動先の各項目の編集可否はその出所から個別に判定します。Scene上のMA Menu Itemなどのcomponentは元Prefabを変更せずinstance overrideとして編集するため、元Prefabの保護状態だけでは読み取り専用にしません。対象の`NotEditable`、immutable Prefab、ホストのPrefab編集許可は確認します。生成ギミックは元の専用Prefabへ保存するため、そのPrefabと編集データ・Controllerの書き込み可否も確認します。AssetProtectionへ直接依存せずUnityの編集許可APIで保護を反映します。個別画面の入力にも編集可否を反映します。追加・登録は元メニューassetを変更せず専用PrefabとMA Menu Installerへ保存するため、参照先メニューassetが保護されていても許可します。Children rootが編集不可なら追加・登録を無効にします。Prefab編集不可とPlay Modeでは変更を無効にします。

読み取り専用の`VRCExpressionsMenu`には右ペインへ「コピーして編集」を表示します。Rootと現在のSubmenuは未選択時の階層設定、通常Itemは選択中の設定欄へ配置します。対象アバターのPrefabと差し替えるScene参照を編集できる場合だけ表示し、出所不明には表示しません。対象メニューと子サブメニューを、編集中Prefabと同じフォルダーの`<Prefab名>.ExpressionMenu`へコピーします。必要な親メニューもコピーしてつなぎ直し、元assetや他アバターを変更しません。複数参照と循環参照は1つのコピーへまとめ、範囲外のメニュー・アイコン・parameter名を保持します。Descriptor、MA Menu Item、MA Menu Installerのメニュー参照だけをinstance overrideとして差し替え、MA Menu Itemを含むPrefab自体はコピーしません。

「コピーして編集」の押下後は、破棄して再読み込みと同じ共通`StatusOverlay`のspinnerと「メニューを差し替え中…」を画面中央に表示します。処理中は画面全体を覆って編集・タブ・Asset選択の操作を無効にし、描画の機会を確保してからコピーと差し替えを開始します。完了・キャンセル・失敗時とViewのdetach時は処理中表示を解除し、背景の有効状態を復元します。開始待ちの間にViewが閉じられた場合は処理を実行しません。

差し替え後も現在の階層・ページと単独Windowの表示元を維持し、通常項目のカードから実行した場合はコピー先の個別編集を開きます。参照の差し替えは1つのUndo groupとし、Undo／Redoで参照を戻せます。作成したコピーassetはUndoで削除せず保持します。失敗時は参照を巻き戻し、今回作成したassetを除去して画面にエラーを表示します。画面表示だけではコピーを作成せず、Scene・アバターPrefabの保存は既存の保存操作で行います。

編集可能な項目のホバー・フォーカスはGMの選択色と1.1倍の拡大で強調します。アイコン・文字は入力を受け取らない表示レイヤーに分離し、無効状態も反映します。ラベルは`UiTextFactory`の12px・100px幅で折り返し、切り捨てません。固定した扇形でホバー判定し、表示レイヤーだけを拡大します。状態変化時だけアニメーションを開始し、反転・破棄時に停止・解放します。未設定アイコンはUnityのGameObject、階層の戻る・型の補助アイコンはGM、個別編集の戻る・追加・NextはFluent UI System Iconsを使用します。

Submenuは保護状態にかかわらず一覧または円形メニューから開きます。子のItemを選ぶと一覧を残して右の編集欄を切り替えます。Submenuの名前・アイコンはその階層の未選択時の右ペインで編集します。専用の詳細画面と右クリック設定は配置しません。

単独Windowの「表示・編集元」でDescriptorとMA Installerの参照asset、MA Menu Itemを選択できます。合成項目は名前・型・アイコン・値・parameter・Puppet軸・ラベル・サブメニューから出所を照合します。複数候補は合成表示で無効にし、編集元選択で確定します。元Controlが差し替わった場合も変更を拒否して再選択を促します。

通常項目は編集元Object、名前、アイコン、ControlType、parameter、value、subMenu、PuppetのsubParametersと方向ラベル・アイコンを設定できます。通常MA Menu Itemは同期・値保存・既定項目・自動値も設定できます。MA Childrenは子構造を保持し、subMenu assetへ置換しません。共有assetの編集はすべての利用アバターへ影響します。

## 専用Prefabと保存

Coreの共通アセットルートの`Animation/ExpressionMenu/<アバターPrefab名>/<ID>/MenuItem.prefab`へ項目ごとのPrefabを作成して接続します。アバター直下には`<アバターPrefab名>_ExpressionMenu`というまとめ用rootを1つ配置し、別IDのフォルダーの`ExpressionMenu.prefab`へ保存・接続します。同名Objectがあれば別名で作成し、再利用は名前ではなく生成Prefabのasset pathで判定します。まとめ用rootへメニュー用componentを追加せず、その子へrootとassetサブメニュー向けの項目Prefabを置いて各MA Menu Installerで登録します。assetサブメニューは`installTargetMenu`を指定します。MA Childrenはその子rootへ置いてChildrenの取り込みを使用します。生成したSubmenuの親子構造はまとめ用root内で維持します。既存の外部MA Childrenへ追加する場合も、そのChildren rootへの配置を維持します。親も生成Prefabなら子の追加・削除時に親Prefabの子構造も保存します。

rootまたはassetサブメニューへの追加時は、アバター直下にSceneの追加overrideとして配置された編集可能な生成Item・Submenuも、子構造と登録先を維持してまとめ用rootへ移します。画面表示だけでは移動せず、保護された項目とアバターPrefabから継承した階層も移動しません。まとめ用rootの作成・項目の移動・追加は同じUndo groupへ記録し、失敗時は巻き戻します。各ItemのrecipeとControllerの保存先・Prefab接続を維持します。

生成Prefabの保存は対象root内の追加・削除とObject overrideを、その生成Prefabのasset pathへ個別Applyします。外側のAvatar Prefabへ一括Applyしません。生成rootはitem一覧から除外し、アバターの配置と他の改変内容の保存は引き続きホスト側が扱います。

書き込み可能な通常SceneのAvatar Prefabインスタンスが対象です。まとめ用rootを含む生成Prefabは上部item一覧から必ず除外します。`assetManager.excludedItemNamePrefixes`は大文字小文字を区別しない名前接頭辞リストで、アバター直下のPrefabを追加除外します。既定は空で、表示対象の指定だけに使用します。

入力確定と選択・チェックの変更で即時適用します。文字・数値はEnterまたはフォーカスを外した時に確定します。設定・動作追加削除・Clip編集・生成Controller・初期状態をUndoへ記録します。専用Prefabのoverride適用前には保存元assetの階層もUndoへ記録し、最後の動作削除で除去した生成componentをSceneと保存元の両方で復元します。専用PrefabとEditor設定・Controllerを保存し、Prefab overrideと作業Scene変更をホストへ通知します。既存メニューassetはそのassetを保存します。配置と既存Scene componentはホストのAvatar Prefab保存を使用します。通常生成項目の削除はGameObjectと付属component、既存MA Menu Itemの削除はそのcomponentだけを除去します。Scene、Git、DBは機能側で保存しません。

## 依存

外部操作は公開`ExpressionMenuApi`から同じModel／recipe／AvatarEvaluationへ接続します。MCP固有の型は持たず、参照はAvatar内のindex path、asset pathとlocal ID、機能側DTOで扱います。調査は出所・編集／コピー可否・動作設定とrevisionを返し、書き込み時は最新のrevisionと出所・編集許可を再検証します。生成Itemの全動作置換は、隔離したrecipeで対象・範囲・property競合を事前検証し、実行時は既存MA ReactiveComponentの変換を含め同じUndo transaction内で置換・生成・保存します。dryRunは保存しません。メニュー変更はSceneをdirtyにして画面の変更検出へ通知し、Avatar Prefab・Sceneの確定保存は既存ホストに任せます。

Coreの公開Localization・ProjectAssetSettings、UI、共有AvatarEditingの編集許可・変更通知・単独Windowへ依存します。設定サービス型のためCore.Contracts、BodyPartCategoryのためCore.Editorも参照します。MAを考慮したメニュー解決・出所照合とパラメーター集計は`Ee4v.Core.AvatarEvaluation.Editor`の`AvatarAuthoringMenu.Read`と`AvatarAuthoringParameters.Read`を使用します。画面と編集処理は`AvatarMenuPage`・`AvatarMenuEntry`・`AvatarParameterInfo`を直接使用し、機能側でメニュー構造やパラメーターを複製しません。ExpressionMenuModelはdraft除外条件と編集・Undo・保存を、recipeは動作ごとのパラメーター候補の絞り込みを所有します。これはビルド前の編集用情報で、NDMFビルド後の最終Expression Menu・パラメーターではありません。AvatarEditingは統合版・単独版の対象と保存契約を揃えるため使用します。他のAvatar機能へ参照しません。VRChat SDK、MA runtime、GM runtime / Editorの実際に使うassemblyのみ参照します。GMは描画の共用に使用し、Edit Modeでアバター実行モジュールを生成しません。

MAは`src/package.json`の対応範囲（1.18.2以上2.0.0未満）で内部resolver `VirtualMenu.ForAvatar`、`RootMenuNode`、Childrenのnode keyへアクセスします。バージョン依存箇所は[Core/AvatarEvaluation](../core/avatar-evaluation.md)へ隔離します。resolver取得・解決失敗時はエラーを表示し、不完全な合成メニューへの編集へ代替しません。

## 手動確認

MCPの同期PNG撮影は`AvatarPreviewRenderer`の隔離スナップショットと`RenderPng`を使用し、同じrecipe・AvatarEvaluationで操作値を評価します。表示用コピーへのMA骨対応とClip／Puppet評価だけを同期的に描画し、Scene用の非同期NDMF Preview Plugin加工や実行時のAnimator遷移・PhysBoneはPlay Modeへ任せます。

- Submenuを開く・戻る・ページ移動・ツリーからの移動・単独Windowの表示元切り替えを続けても、設定変更がなければメニューの再解決やコピー可否のためのアバター再走査を行わないこと。外部Inspectorでの名前・型・参照の変更、Hierarchy変更、Undo／Redo、Project変更、対象変更・タブ再接続の後は次の画面更新に反映すること。キャッシュ再利用中も本来のSubmenuと通常Itemの判定、選択位置・ページ保持が一致すること。ドラッグ中の同じ移動先で強調・説明がちらつかず、移動不可の判定・確定時検証・取消を維持すること。

- Toggle・Button・Puppetに未使用の`subMenu`参照が残っている場合と、通常MA Menu ItemにChildren設定が残っている場合でも、円形メニュー・カード・ツリーが通常Itemとして扱うこと。「開く」や子の展開がなく個別編集を開けること、合成表示と単独Windowの編集元選択で一致すること、表示前後で元asset・componentが変化しないこと。本来のSubmenuは引き続き開けること。
