# Expression Menu

`src/Editor/Feature/Avatar/ExpressionMenu`の`Ee4v.ExpressionMenu.Editor`は、Unity 2022.3 / VRChatでギミック制作とExpression Menu編集を扱います。AssetManagerの「Expression Menu」カテゴリと単独の`ee4v/Window/Avatar/Expression Menu`が同じ`ExpressionMenuView`を使用します。動作確認はPlay Modeの既存GestureManager Controlsで行います。

## ギミックエディター

空のメニューでも空状態の説明文は表示せず、円形メニューと一覧末尾の追加カードから項目を作成できます。

右側のカード一覧の末尾に「＋／追加」カードを配置し、円形メニューと同じItem／Submenuの二択・編集許可で現在の階層へ登録します。ページ分割時は円形メニューと同じく最後のページだけへ表示します。追加カードは項目カードと同じ幅・最小高さで、大きい＋アイコンと「追加」を中央に表示します。登録済み項目と並び替えの対象には含めません。ツリーの見出しは配置しません。編集できない項目はツリーの名前の右、カードの名前欄の上の右端に、マテリアル画面と同じ中立色の`Badge`で「読取専用」を表示します。Submenuはラベルがある場合も開けます。Rootもホストの編集許可と表示元のメニューasset・Children root・MA項目・アバターrootの書き込み可否を判定し、編集不可ならツリーのRoot行と現在位置欄へ同じラベルを表示します。固定のRoot名・アイコンであることだけでは読取専用と判定しません。Rootの閲覧・階層移動と、別Prefabへ保存する追加操作の許可は従来の判定を維持します。

全体画面の左上に機能名の「Expression Menu」見出しは配置しません。ツリーのRootアイコンは14pxで描画し、余白を含めた20pxのアイコン領域と名前の開始位置を他の行へ揃えます。

ツリーの「読取専用」ラベルは行のリンクボタン内の右端に配置し、選択・ホバーの背景へ収めます。名前が長い場合は名前だけを省略し、ラベルの幅を保持します。ラベル上からも行のクリック・階層移動を行えます。

全体画面の円形メニュー下にRoot・Submenu・通常項目のメニュー階層ツリーを配置します。アイコン・名前を表示し、現在の階層を強調します。RootとSubmenuのクリックはその階層の先頭ページへ移動し、保護状態にかかわらず開けます。通常項目のクリックは対応する階層・ページの個別編集を開き、保護された項目では無効にします。子項目がある行はchevronで展開・折りたたみでき、初期表示はRootを展開します。円形メニューや一覧から階層を変えた場合は現在位置の祖先を自動で展開し、選択行を表示領域へ収めます。展開状態は同じ表示元の画面更新で保持し、表示元変更時は初期化します。ツリーは最大280pxの高さに収め、多数の階層を展開した場合だけ内部をスクロールします。同じメニューを複数箇所で参照する場合は各pathへ表示し、循環参照は祖先と同じメニューを再展開せず止めます。個別編集画面にはツリーを配置しません。

ツリーの項目名を6px以上ドラッグすると移動を開始します。Root・Submenuの中央へドロップすると、その階層の末尾へ移動します。同じ階層の通常項目の上下半分、Submenuの上下端へドロップすると挿入線を表示して並び替えます。右側のカードのハンドルからツリーへのドロップも共通の処理を使用します。移動先の行とカーソルに追従する項目名・移動先を表示し、無効な場所は赤く表示します。保護・出所不明・満杯の移動先、自分自身・子孫への移動や、保護項目・異なる出所を越える並び替えを拒否します。Root自体はドラッグできません。ツリー上下端で自動スクロールし、Esc・範囲外・capture喪失・画面離脱は変更せず取り消します。移動は既存のRelocate／MoveのUndo・保存契約を使用し、完了後は移動先の階層を表示します。

全体画面の一覧カードは144pxのアイコンを維持し、カード内の上下paddingを12px、カード外の上下paddingを6px、最小高さを194pxにします。2列4行の一覧を約900pxの表示領域へ収め、不要な縦スクロールを避けます。表示領域が足りない場合や個別編集の内容が多い場合はスクロールを維持し、内容を隠しません。

`ExpressionMenuView`は1ペインで全体画面と個別編集画面を切り替えます。全体画面は利用可能な横幅を使用し、円形メニューの列と表示中の項目の簡易編集カードを横に配置します。一覧の幅が900px以上ならカードを2列、それ未満では1列とし、狭い画面では円形メニューの下へ配置します。144pxのアイコンプレビュー・Texture選択欄、名前の入力欄を配置します。Itemには「編集」、Submenuには「開く」を配置します。編集可能な項目へ「移動」「削除」を表示し、保護された項目では編集・移動・削除だけを無効にします。円形メニューの上には下端の区切り線と80pxのアイコンプレビュー・Texture選択欄、名前の入力欄だけを配置します。現在のSubmenuの名前・アイコンを直接編集し、専用の個別編集画面は表示しません。Rootも同じ配置にし、固定のRoot名とフォルダーアイコンを変更不可で表示します。見出し・階層path・項目数・ページ番号・詳細編集ボタンは配置しません。アイコンプレビューに背景色を付けず、透過Textureのalphaを全体画面・個別編集のどちらでも保持します。名前・アイコンだけの変更は型、parameter、初期値、同期設定や動作を変更しません。円形メニューのItemまたは「編集」で個別編集画面へ移動し、円形メニューは表示しません。個別編集の内容は最大680px幅で中央配置し、スクロール領域の外の左上へ「メニューへ戻る」を配置します。同じ階層・ページの全体画面へ戻り、編集内容を保持します。

個別編集では上部の枠内に144px幅のアイコン、その右に名前・タイプ選択・初期値を縦に配置し、動作カードを枠の下へ配置します。アイコンプレビューの下にTexture選択欄を内包し、枠全体でTextureのドラッグ＆ドロップを受け付けます。アイコン未設定時はUnityのGameObjectアイコンを表示し、全体画面と円形メニューも同じ代替アイコンを使用します。保存値と選択欄は未設定のまま保持します。操作タイプは見出しを表示せずツールチップで示し、説明文と未設定時の案内文は配置しません。同期は各動作カードへ配置します。Submenuは全体画面の名前・アイコン入力だけを使用し、対応する動作エディターを持たない通常項目は既存の詳細フォームで編集します。統合画面は専用ExpressionMenuHostで他カテゴリのプレビュー・設定領域と切り替えます。単独Windowの最小幅は480pxです。

円形メニューの「＋／追加」はItem／Submenuの二択を表示します。ItemはToggleを初期タイプとした、動作が空の専用Prefabを作成し、表示中のrootまたはサブメニューへ即時登録して個別編集画面を開きます。タイプはToggle・0〜100・Button・Puppetの4種類です。Puppetはタイプの選択肢を1つにまとめ、その設定内で2 Axis／4 Axisを選択します。「動作を追加」は動作セクションの見出しに配置し、選択タイプへ対応する動作だけを列挙します。同じ種類を複数追加でき、各カードの「動作を削除」でその動作だけを除去します。最後の動作を削除してもメニュー項目は残ります。全動作は1つのMenu Itemに属し、Puppetでは各動作に操作する軸を指定します。

| 操作タイプ | 利用可能な動作 | 初期状態 |
| --- | --- | --- |
| Toggle（ON／OFF） | オブジェクト表示／非表示、マテリアル差し替え、BlendShape変更、パラメータの値を変更、マテリアルのパラメーター変更、Transform変更、Componentの有効切り替え | ON／OFF |
| 0〜100（連続値） | BlendShape変更、パラメータの値を変更、マテリアルのパラメーター変更、Transform変更 | 0〜100の数値 |
| Button（実行） | パラメータの値を変更（Trigger実行、Bool／Int／FloatのSet） | OFF固定、値保存なし |
| Puppet（軸操作） | Transform変更 | 各軸0、中心位置 |

Puppetの新規動作はTransform変更だけを提供します。ほかの保存済み動作カードも表示・編集・削除できます。Buttonの候補とカード名は他のタイプと共通の「パラメータの値を変更」を使用します。

ButtonはSDKのButton controlを使用し、クリック時の一時的なONとSDKによるOFFへの復帰で動作します。初期値の入力は配置しません。Puppetの2 Axisは左右・上下の−1〜1、4 Axisは上・右・下・左の0〜1を使用し、各動作の軸選択と範囲へ反映します。左右・上下では範囲の左端が−100、右端が100に対応し、中心は両端の中間値になります。4 Axisの左端は0、右端は100です。Puppetにも初期値の入力は配置しません。軸parameterは固有の共通IDへ軸名を付けて生成し、各軸を使用する同期ONの動作がある場合だけ同期します。タイプや軸数の変更でも共通IDを保持し、不要になった生成軸parameter宣言を除去します。

他プレイヤーへの同期は動作カードごとに設定します。ONの動作は他プレイヤーにも適用し、OFFの動作は本人だけに適用します。同じItemに両者を組み合わせられます。動作の新規追加時は同期ONです。既存のMA ReactiveComponentやClip動作がある項目はToggleとして扱います。

操作タイプとPuppetの軸数の切り替えは、破棄対象がある場合に表情のジェスチャー割り当てと同じ共通`ConfirmationOverlay`で確認します。中立色の本文と区切り線のある操作欄を使用し、赤い「破棄して変更」を左端、通常の「編集を続ける」を右端へ配置します。動作カード・生成MA ReactiveComponentがなく、現在の初期状態がOFF／0の場合は確認せず即時に切り替えます。名前・アイコンだけの編集では確認しません。追加済みの空の動作カードも破棄対象とします。確認中はタイプと軸数の表示、保存データを元のまま保持し、背後のWindowを操作できません。「破棄して変更」で初期状態をOFF／0へ戻し、すべての動作カード・対象・Clip参照・動作ごとの同期設定と生成MA ReactiveComponentを除去して、新しい型のparameter・Controllerを構成します。名前・アイコン・メニュー登録先・固有parameter IDと素材Clipは保持します。値保存はButtonでは無効、他のタイプでは有効です。「編集を続ける」またはEscは変更せず閉じます。画面を離れた場合も確認を取り消します。失敗した場合はUndo transactionで元へ戻し、overlay内にエラーを表示して元のタイプに留まります。確定した変更はUndo／Redoの対象です。

Itemの個別編集は選択した項目の出所MA Menu Itemを参照します。Toggleでは「初期状態をONにする」、連続値では「初期値（0〜100）」で全動作共通の初期状態を設定します。名前・アイコンやタイプを更新しても個別編集画面を維持し、全体画面へ戻ると更新された円形メニューと簡易編集行を表示します。メニュー未登録で保持する操作は設けません。

画面表示・再描画だけでは既存データを変更しません。メニュー未登録の項目は編集元候補へ含めません。個別編集の項目削除は、生成したギミックのScene上のGameObjectと付属componentをUndoで除去して全体画面へ戻ります。メニュー未登録のScene上の定義は残しません。保存済みassetは保持します。既存の対応MA項目も個別フォームで扱いますが、動作カードの追加・削除はee4v生成Prefabだけに許可します。

## ItemとSubmenuの作成

Item・Submenuとも現在のrootまたはサブメニューへ追加し、出所componentで階層・ページを特定します。Itemは個別編集画面を開きます。SubmenuはMA Children構成で作成し、作成後にその階層の全体画面へ入ります。その中の「＋」から再びItem／Submenuを追加できます。生成Submenuへparameter・同期・既定値・型切り替えなどの動作用設定は表示しません。

専用PrefabはMA Menu Itemを使用します。ItemはToggle、空の動作設定で作成します。保存用ControlはToggle、固有パラメーター名、値1、同期・値保存あり、初期OFFです。タイプ選択でToggle・RadialPuppet・Button・TwoAxisPuppet・FourAxisPuppetへ更新します。初期状態の編集はToggleとRadialPuppetに配置します。SubmenuはSubMenu型、空parameter、値0、同期・値保存・既定項目なしで作成します。`MenuSource`はChildrenにします。動作テンプレートの選択はItemの「動作を追加」だけに配置します。

Toggleの表示／非表示・マテリアル差し替え・BlendShape変更はEditor専用recipeの`MenuReactiveAction`へ保持し、カードごとのON/OFF ClipとFXレイヤーを生成します。Object Toggleは対象とON時の表示、Material Swapは変更前後のMaterial、Shape Changerは対象SkinnedMesh・BlendShape・ON時の値（0〜100）を編集します。いずれも対象行を追加・削除できます。対象行の編集は全体の初期ON/OFFを変更しません。Material Swapは変更元と変更先のObjectFieldを矢印で結び、見出し付きの2列を1行に配置します。新規Material Swapはアバター全体を対象とし、指定した元Materialを使用する各Rendererのslotへ変更先を割り当てます。OFFは設定時の値へ戻します。

既存のMA ReactiveComponentは最寄りのMenu Itemに属するものだけをフォームへ表示します。ee4v生成項目でrecipeを変更すると、既存の対象・値・反転と同期設定をrecipeへ引き継ぎ、元componentをUndo付きで除去します。描画だけでは変換しません。Quick SwapとBlendShape削除は変換を拒否し、元の設定を保持します。既存の外部MA項目はcomponentの設定編集を維持し、動作単位の同期変更と動作カードの追加・削除は許可しません。

全動作はメニューの共通BoolまたはFloat、Puppetでは指定した軸のFloatを参照します。同期ONの動作が1つ以上あるときだけ対応する入力parameterを同期し、すべてOFFならローカルparameterとして構成します。同期OFFの動作レイヤーはmotionを持たないLocalOnly stateを既定とし、組み込みBool `IsLocal`がtrueのときだけ動作stateへ遷移します。他プレイヤー側ではそのレイヤーからプロパティを書き込みません。初期ONや連続値の初期値がある場合も同じ条件を適用します。入力parameterとカードごとの同期フラグ・レイヤー制御により、同期動作と本人専用動作を1つのメニューで操作します。

連続値のBlendShape変更は、対象SkinnedMesh・BlendShapeと「範囲」を指定します。「範囲」は2つの数値入力を区切り記号とともに1行へ並べ、左を操作値0、右を操作値100でのBlendShape値として扱います。Puppetの2 Axisだけは左を−100として扱います。各入力のtooltipで両端の意味を示します。複数の対象行を追加・削除でき、両端の値は0〜100で検証します。逆方向の範囲も指定できます。0〜100タイプは1秒の線形Clipを共通Floatでサンプルします。Puppetは両端の固定値Clipを指定軸の1D BlendTreeで補間し、2 Axisでは−1／1、4 Axisでは0／1をthresholdにします。連続値では表示切り替えとMaterial差し替えのテンプレートを表示しません。動作カードに常設の説明文は表示しません。

対象未指定の行を保存・再読込した場合や、指定pathにSkinnedMeshRendererが存在しない場合も編集欄を保持します。Unityのmissing-component参照は実際のnullへ正規化し、meshへアクセスせず対象の再指定・行削除を行えるようにします。

MA対象は編集中アバター内部に限定し、rootの無効化を拒否します。対象をroot相対pathのAvatarObjectReferenceへ変換し、同名の兄弟Objectと名前に`/`を含むObjectを拒否します。対象の削除・改名、存在しないBlendShapeはエラー表示します。

## マテリアルのパラメーター変更

Toggleと0〜100タイプで追加できます。カードごとの同期と複数の対象行を持つEditor専用recipeの `MenuMaterialValueAction` として保持します。各行はアバター内のRendererとMaterialの設定項目を選びます。ShaderのFloat／Range／Integer・Color（HDRを含む）・Vector・Texture、Textureの倍率／オフセット、Shaderキーワード、Shader、Render Queue、GPU Instancing、Double Sided GI、Global Illumination Flagsを列挙します。非表示のShaderプロパティも含めます。TextureのNoScaleOffset指定は尊重します。使用Materialにある設定を列挙し、Shaderの項目は表示名と内部名を併記します。同じObjectに複数のRendererがある場合、先頭のRendererだけを対象にできます。

Toggleは現在値のOFFと編集するONを2列に並べます。OFFは編集不可です。値の型に合わせて数値・整数・チェック・Color・成分ごとの入力・Texture／Shader参照を表示します。0〜100タイプはUnityのRenderer animation bindingが提供する項目だけを候補にし、両端の値を入力して1秒の線形Clipで補間します。対応する数値・Color・Vector・Texture倍率／オフセットを使用できます。負の値と逆方向の範囲を使用でき、非有限値・整数項目の小数を拒否します。ShaderのRange属性は入力範囲として強制しません。

アニメーション対応項目はRendererの `material.<property>` を操作します。同じ名前の項目を持つ複数のMaterial slotに共通の値を適用し、OFFはUnityのbindingから取得した現在値（通常は先頭Materialの値）へ戻します。slot別の数値復帰は提供しません。アニメーションできない項目はToggle専用で、MaterialのコピーへON設定を適用し、Rendererの該当slotの参照を切り替えます。Cull・ZWrite・Blend・Stencil等のrender stateもコピーで扱います。一般的なプロパティ名とShaderの依存ソース内のShaderLab命令から対象を識別し、連続値の候補から除外します。同じカード内のTexture・キーワード等の変更はslotごとに1つのコピーへまとめます。OFFは各slotの元Material参照へ復帰します。生成MaterialはControllerのsubassetとして保存し、元Material assetは変更しません。

対象未指定の行を保持して生成から除外します。Renderer・項目の変更時は両端と参照を現在値で初期化します。描画だけでは保存値を変更しません。Textureのdimension、Render Queue（−1〜5000）、GI flags（0〜7）、チェック（0／1）、非有限値、対象消失、アバター外・曖昧なpathと同一bindingの競合を検証します。Materialの差し替えが同じslotと競合する場合も拒否します。不正な編集は元へ戻して入力欄とエラーを表示し、再指定・行削除を行えます。同期・Undo／Redo・保存・タイプ変更時の破棄には他の動作と同じ契約を使用します。ButtonとPuppetの候補には含めません。

## Transform変更

Toggle・0〜100・Puppetで追加できます。 `MenuTransformAction` のカードに複数の対象Objectを保持し、各対象で位置・回転・サイズの操作を個別に有効にできます。値はlocalPosition・localEulerAngles（度）・localScaleを使用します。対象変更時は両端を現在値で初期化します。Toggleは編集不可の現在値OFFと編集するON、0〜100は両端のXYZ入力を並べます。0〜100は各成分を線形に補間します。未設定の行・全操作OFFの行を保持します。

Puppetの2 Axisは入力方向を左右／上下から選び、XYZの1軸を割り当てます。4 Axisは左右と上下へ異なるXYZの2軸を割り当てます。左右はRight／Left、上下はUp／Downの値から操作し、同じ軸を選んだ際はもう一方の割り当てを入れ替えて重複を防ぎます。位置・回転・サイズで共通の軸割り当てを使用し、各操作の選択軸の両端だけを編集します。中心は両端の中間値、未選択のXYZ成分は設定時の現在値です。2 Axisは−1／0／1の1D BlendTree、4 Axisは四方向parameterを使用する入れ子の1D BlendTreeと9つの姿勢Clipで補間します。回転の補間にはUnityのBlendTreeの回転補間を使用します。2 Axisは選択した入力だけ、4 Axisは四方向すべてに動作の同期フラグを反映します。

非有限値・消失した対象・アバター外・曖昧なpath・不正な軸指定・他の動作との同一binding競合を拒否します。QuaternionとEulerの別表現による回転競合も検証します。FXレイヤーとClipを生成し、ToggleのOFF復帰、同期のLocalOnly gate、Undo／Redo・保存・タイプ変更時の破棄には他の動作と同じ契約を使用します。Buttonには提供しません。

## Componentの有効切り替え

Toggleで追加できます。 `MenuComponentAction` の各行で対象ObjectとComponent、ON時の有効状態を設定します。OFFは現在の `m_Enabled` 値を示す編集不可のチェックで、復帰Clipも現在値を取得します。Renderer・Collider・Animator・Light・Camera・AudioSource・Cloth・Animation・Unity Constraintと対応するVRC Dynamics／Spatial Audio／HeadChop／Station componentのうち、Unityが `m_Enabled` のanimation bindingを提供するものを候補にします。対象Objectに同型Componentが複数ある場合は識別できないため、その型を候補から除外します。MA・ee4v・Descriptor、アバターDescriptorと同じObjectのAnimatorは候補に含めません。

複数の対象行と動作ごとの同期を設定でき、未指定行を保持します。対象消失・非対応のComponent・同一binding競合は編集を拒否して復元し、再指定・行削除を行えるカードを保持します。FX生成・OFF復帰・Undo／Redo・保存・タイプ変更時の破棄には他の動作と同じ契約を使用します。

## パラメータの値を変更

動作カードでパラメータ名を設定します。ToggleはBool、連続値・保存済みPuppet動作はFloat／Intを使用し、型の選択欄を配置しません。ButtonだけはTrigger・Bool・Int・Floatの型を扱います。名前は直接入力でき、Playable Layer、MA Merge Animator、Expression Parameters、公開MA Parametersから型付きの候補を選択できます。既知の名前は型を自動反映し、Buttonの型選択欄を無効にします。未知の名前は数値操作ではFloat、Buttonでは初期Triggerとし、Buttonの型を選択できます。TriggerでExpression Parametersに同名宣言があるものは候補から除きます。MAのprivate・prefix定義、自分自身の入力parameterは候補へ含めません。Toggleは「設定する値」の下に「メニューOFF時」「メニューON時」の見出しを配置し、それぞれFalse／Trueを選択します。連続値は両端の範囲を1行で編集します。ButtonのTriggerは値の入力を設けず、Boolはチェック、Intは整数、Floatは小数の「設定する値」を1つ表示します。型を変更すると値を初期化します。対象未指定のカードは保持し、動作レイヤーへ含めません。

設定はEditor専用recipeの`MenuParameterAction`へ保持します。ToggleはFXレイヤーのOFF／ON stateの`VRCAvatarParameterDriver`でSetし、初期状態も適用します。Buttonはメニュー入力用BoolをSDKのButtonで操作し、ONへ入ったときだけDriverのSetで対象Triggerを実行するか、Bool／Int／Floatを指定値に設定します。OFF・初期状態にはDriverを配置せず、起動時の誤実行を防ぎ、Buttonの復帰後も設定した値を保持します。対象TriggerはAnimator Controllerだけに宣言し、Expression Parameters／MA Parametersには追加しません。同期は入力Boolと各プレイヤー側の実行で扱います。連続値・Puppetは2つのstateを各0.02秒以上保持して交互に遷移し、stateへ入るたびにCopy／Convert Rangeで入力Floatを指定範囲へ写します。Puppetは動作が指定した軸をsourceとし、2 Axisでは−1〜1、4 Axisでは0〜1を使用します。止めた操作値も継続して適用し、逆方向の範囲も使用できます。Intの中間値はSDKの切り捨てを使用します。時計用Clipは共通parameter IDに`/CopyClock`を付けた内部Floatだけを操作します。

カードの同期設定は共通parameterの同期判定とIsLocal gate・DriverのlocalOnlyへ反映します。対象parameterの既存のExpression Parameters／MA Parametersの同期・保存宣言は変更しません。生成Controllerの対象parameterは既存Controller・Expression Parameters・明示的なMA Parametersの初期値を引き継ぎ、Buttonを押す前の値を維持します。既存宣言で同期されている対象の値は、その宣言に従って同期されます。新しい対象名は生成FX Controllerだけへ型を宣言し、同期ONの場合は共通parameterから各プレイヤー側のDriverで適用します。

組み込みparameter、自分自身の共通parameter・時計parameter、同じItem内の重複した対象名、メニューの型と一致しない既存parameterを拒否します。非有限値、Boolの0／1以外、Intの小数を拒否し、Expression Parametersで宣言されたIntは0〜255・Floatは−1〜1も検証します。不正な編集はUndo transactionで元に戻し、入力と動作カードを再表示してエラーを示します。削除・型切り替え・保存・Undo／Redoは他の動作と同じ契約を使用します。

## 登録済みのClip動作

Animation Clipは新規追加のテンプレートへ含めません。登録済みのClipカードは引き続き表示・編集・削除できます。アバターroot相対の通常ClipをON/OFFで指定し、プロパティ操作・エフェクトなどを同じメニューで切り替えます。OFF省略時はONが操作するプロパティについて設定時のアバターの値を取得し、復帰用Clipを生成します。ON/OFFの片方だけにあるプロパティも、もう片方に設定時の値を補います。素材Clipは変更しません。ON未指定のカードはControllerへ含めません。

設定は専用Prefabと同じフォルダのEditor専用`Gimmick.asset`へ保持し、空のギミックの識別にも使用します。`Gimmick.controller`へカードごとのFXレイヤー、ON/OFF stateとClipのコピーを生成します。共通Boolパラメーターで即時遷移し、Write DefaultsはOFF、レイヤーweightは1です。MA Merge AnimatorをAbsolute path / FX / Appendで接続します。初期ON/OFF変更はControllerのparameter defaultと初期stateにも反映します。有効なClip・parameter動作がすべてなくなると生成Merge Animatorを除去します。

連続値ではON用Clipだけを指定し、操作値0で先頭、100で末尾をサンプルします。生成コピーのloopTimeを無効にし、FXレイヤーの単一Value stateへmotion time parameterとspeed 0を設定します。素材Clipは変更せず、OFF用参照は保持したままフォームから隠します。時間経過での再生は行いません。生成ControllerのFloat defaultは初期値を100で割った値です。RadialPuppetの主parameterは空とし、subParametersの先頭へ固有パラメーターを設定します。同じGameObjectへMA Parametersを配置してFloat・明示的default・値保存・localOnly（同期設定の反転）を指定します。動作が未設定でもこのparameter設定は保持します。Toggleへ戻すと生成したFloat設定を除去します。

Legacy／Humanoid Clip、解決できない対象・プロパティ、アバターrootの表示操作、同名pathを拒否します。生成する全動作カード間で同じプロパティを操作することも拒否します。外部Clip変更後はカードでClipを再指定して生成物を更新します。動作確認はPlay Modeで行います。

Clip入力時は、変更の確定とUndo記録の前に、対象Object・Component・BlendShape・プロパティの存在と全動作間の競合、復帰用Clipの生成を検証します。存在しないComponentへAnimationUtilityでアクセスしません。不適合なClipは入力欄を元の参照へ戻し、同じ編集欄にエラーを表示します。対象を解決できない場合はClip名・対象path・Component型・プロパティを添えます。保存済みrecipe・Controller・Prefabと選択中のメニュー、動作カードを保持します。

## BlendShapeの選択

Toggleと連続値は共通の対象選択フォームを使用します。対象行ごとにSkinnedMeshRendererのObjectFieldと、そのmeshのBlendShape名を列挙するドロップダウンを縦に配置します。対象未指定時はBlendShapeの選択を無効にし、Renderer変更時は最初のBlendShapeを選択します。Toggleはその下に「OFF → ON」の2つの数値欄を1行で表示します。OFFは選択したRendererの現在のBlendShape値を読み取る編集不可の欄で、対象とBlendShapeの選択後に更新します。OFF値はrecipeへ保存せず、生成Clipの復帰値も設定時の現在値から取得します。ONだけを0〜100で編集します。連続値は2つの値を1行にした範囲入力を表示します。「対象を追加」「対象を削除」で複数の対象行を編集し、対象とBlendShapeが未指定の行も保持します。未設定の行はClip生成から除外し、指定後に動作へ反映します。既存の対象と値は描画だけでは変更しません。指定済みの対象やBlendShapeが消失した場合はエラーを表示し、再指定と行削除を行えます。不正な値や更新失敗時は入力欄を元に戻します。

## 並び替え

一覧の「移動」は共通overlayへ移動先の選択欄と「移動」「キャンセル」を表示します。Rootと別のSubmenuを階層pathで列挙し、現在の階層、自分自身・子孫、保護された編集元、8項目に達した移動先を除外します。候補がない場合はその旨を表示します。assetのControlは移動先assetの末尾へ移し、MA Childrenへ移す場合は同じControlを持つ専用MA Menu Item Prefabへ変換します。専用生成MA項目は同じPrefabを使用して移動先へ再配置し、Childrenでは自身のInstallerを外し、assetまたはRootではInstallerの登録先を変更します。名前・アイコン・parameter・動作・子メニューを保持します。階層とInstallerの変更はアバターのPrefab overrideとして保持し、ホストのアバター保存で確定します。移動中に生成親Prefabへ階層変更をApplyせず、Sceneと保存元の構造変更を二重にUndoへ記録しません。通常SceneのMA項目と追加GameObject overrideも移動できます。既存Prefabに組み込まれた非生成MA項目と、Menu assetを併用するInstallerは階層構造を変更できないため対象外です。移動は1回のUndo／Redoで戻せ、失敗時はSceneと変更した保存元を復元します。

一覧の「削除」はItemと空のSubmenuを即時削除します。中に項目があるSubmenuだけ共通の警告overlayを表示し、「中身ごと削除」または「キャンセル」を選べます。取消とEscでは設定を保持します。assetのSubmenuは親Controlの登録を除去し、共有される参照先asset自体は削除しません。生成MA項目は配下のGameObjectを含めて除去し、生成親Prefabを保存します。通常MA項目はMenu Item componentの登録を除去します。

項目カードの左端にFluent UIの6点グリップを使用するドラッグハンドルを配置します。番号と前後移動ボタンは配置しません。同じメニューassetのControl間、または同じ親を持つMA Menu Item間で順番を変更できます。ドラッグ中は元のカードに代えて、アイコンと名前を持つカード1枚分の空き枠を挿入し、周囲のカードを移動後の順番へ配置します。有効な移動先の空き枠と挿入線をfocus色で強調します。1列ではカードの上下半分、2列では左右半分で前後の挿入位置を選び、カード間の余白でも最寄りの位置を表示します。判定には開始時の配置を使い、プレビューによる再配置で移動先が振動しないようにします。移動不可の場所では元の位置へ空き枠を戻し、変更しません。ハンドルだけがドラッグを開始し、入力欄や開くボタンには影響しません。スクロール端で自動スクロールし、Esc・キャプチャ喪失・一覧外でのドロップ・画面離脱は変更せず取り消し、空き枠と一時的な配置を除去します。キーボードはハンドルへフォーカスして矢印キーで隣へ移動できます。名前・アイコン・parameter・動作設定は変更せず、円形メニューと一覧を再解決します。ドラッグは表示中のページ内で行い、矢印キーでページ境界を越えた場合は移動先のページを表示します。

保護・出所不明の項目、異なるメニューassetやassetとMA間、異なる親を持つMA間の移動は無効です。移動元から移動先までの全項目も確認し、保護された項目や保存元の境界を飛び越える移動を拒否します。MAでは親Transformと両項目の編集可否も確認します。assetはControl配列の順番を保存し、MAは兄弟順を変更します。生成Prefab内では対応する元Prefabの兄弟順だけも保存し、アバターの他のoverrideは適用しません。順番の変更はUndo／Redoに対応します。

## 表示と出所

統合画面と単独Windowは3Dプレビューを表示せず、1ペインの全体画面と個別編集画面を使用します。統合画面は合成表示に固定し、単独Windowの全体画面だけに表示・編集元の選択欄とメニュー名を表示します。説明用HintBox、再読み込み・メニューasset保存ボタンは配置しません。編集エラーと読み取り専用の案内は必要時に表示します。選択と変更の後にメニューを解決し直します。

初期表示はDescriptorへMA Menu Installer、Menu Item、Menu Group、Menu Install Targetを解決した構成です。円形メニューはGestureManagerの`GmgCircleElement`、`RadialMenuUtility`、`RadialCursor`を使用し、300pxの円、100pxの中央円、50pxのアイコン、扇形のグラデーション・区切り線・設定色・カーソルを描画します。root初期ページには項目と追加またはNextを表示します。階層内と2ページ目以降は「戻る」を先頭へ配置します。時計回りに項目、末尾操作の順で均等に分割します。

8項目超の合成メニューは7項目とNextへ分割します。Nextがあるページの末尾はNextだけ、最後のページだけに「＋／追加」を配置します。簡易編集行も現在のページの項目だけを表示します。追加後は該当項目のページを保持して個別編集を開きます。追加・戻る・Nextはassetの8項目上限に含めません。ページ移動は表示だけで元assetを分割しません。

保護・読み取り専用・出所不明の項目は名前・アイコンの入力と編集・移動・削除を無効にします。円形プレビューでも編集だけを行うItemは文字・主アイコン・型の補助アイコン・扇形をグレーアウトします。Submenuは保護状態にかかわらず円形メニューと「開く」から移動でき、ホバー強調も有効です。一覧の移動・削除ボタンは編集不可の場合に無効表示します。移動先の各項目の編集可否はその出所から個別に判定します。Scene componentは対応する元Prefabも`AssetDatabase.IsOpenForEdit`で確認します。生成ギミックの編集データ・Controllerも書き込み可否を確認します。AssetProtectionへ直接依存せずUnityの編集許可APIで保護を反映します。個別画面の入力にも編集可否を反映します。追加・登録は元メニューassetを変更せず専用PrefabとMA Menu Installerへ保存するため、参照先メニューassetが保護されていても許可します。Children rootが編集不可なら追加・登録を無効にします。Prefab編集不可とPlay Modeでは変更を無効にします。

編集可能な項目のホバー・フォーカスはGMの選択色と1.1倍の拡大で強調します。アイコン・文字は入力を受け取らない表示レイヤーに分離し、無効状態も反映します。ラベルは`UiTextFactory`の12px・100px幅で折り返し、切り捨てません。固定した扇形でホバー判定し、表示レイヤーだけを拡大します。状態変化時だけアニメーションを開始し、反転・破棄時に停止・解放します。未設定アイコンはUnityのGameObject、階層の戻る・型の補助アイコンはGM、個別編集の戻る・追加・NextはFluent UI System Iconsを使用します。

Submenuは保護状態にかかわらず円形メニューまたは開くボタンからその階層の全体画面を開きます。子のItemを選ぶと個別編集へ移動します。Submenu自体は親の項目カードか、円形メニュー下のアイコン・名前で直接編集します。Submenu用の詳細編集画面と右クリックの設定操作は配置しません。

単独Windowの「表示・編集元」でDescriptorとMA Installerの参照asset、MA Menu Itemを選択できます。合成項目は名前・型・アイコン・値・parameter・Puppet軸・ラベル・サブメニューから出所を照合します。複数候補は合成表示で無効にし、編集元選択で確定します。元Controlが差し替わった場合も変更を拒否して再選択を促します。

通常項目は編集元Object、名前、アイコン、ControlType、parameter、value、subMenu、PuppetのsubParametersと方向ラベル・アイコンを設定できます。通常MA Menu Itemは同期・値保存・既定項目・自動値も設定できます。MA Childrenは子構造を保持し、subMenu assetへ置換しません。共有assetの編集はすべての利用アバターへ影響します。

## 専用Prefabと保存

Coreの共通アセットルートの`Animation/ExpressionMenu/<アバターPrefab名>/<ID>/MenuItem.prefab`へ項目ごとのPrefabを作成して接続します。アバター直下には`<アバターPrefab名>_ExpressionMenu`というまとめ用rootを1つ配置し、別IDのフォルダーの`ExpressionMenu.prefab`へ保存・接続します。同名Objectがあれば別名で作成し、再利用は名前ではなく生成Prefabのasset pathで判定します。まとめ用rootへメニュー用componentを追加せず、その子へrootとassetサブメニュー向けの項目Prefabを置いて各MA Menu Installerで登録します。assetサブメニューは`installTargetMenu`を指定します。MA Childrenはその子rootへ置いてChildrenの取り込みを使用します。生成したSubmenuの親子構造はまとめ用root内で維持します。既存の外部MA Childrenへ追加する場合も、そのChildren rootへの配置を維持します。親も生成Prefabなら子の追加・削除時に親Prefabの子構造も保存します。

rootまたはassetサブメニューへの追加時は、アバター直下にSceneの追加overrideとして配置された編集可能な生成Item・Submenuも、子構造と登録先を維持してまとめ用rootへ移します。画面表示だけでは移動せず、保護された項目とアバターPrefabから継承した階層も移動しません。まとめ用rootの作成・項目の移動・追加は同じUndo groupへ記録し、失敗時は巻き戻します。各ItemのrecipeとControllerの保存先・Prefab接続を維持します。

生成Prefabの保存は対象root内の追加・削除とObject overrideを、その生成Prefabのasset pathへ個別Applyします。外側のAvatar Prefabへ一括Applyしません。生成rootはitem一覧から除外し、アバターの配置と他の改変内容の保存は引き続きホスト側が扱います。

書き込み可能な通常SceneのAvatar Prefabインスタンスが対象です。まとめ用rootを含む生成Prefabは上部item一覧から必ず除外します。`assetManager.excludedItemNamePrefixes`は大文字小文字を区別しない名前接頭辞リストで、アバター直下のPrefabを追加除外します。既定は空で、表示対象の指定だけに使用します。

入力確定と選択・チェックの変更で即時適用します。文字・数値はEnterまたはフォーカスを外した時に確定します。設定・動作追加削除・Clip編集・生成Controller・初期状態をUndoへ記録します。専用Prefabのoverride適用前には保存元assetの階層もUndoへ記録し、最後の動作削除で除去した生成componentをSceneと保存元の両方で復元します。専用PrefabとEditor設定・Controllerを保存し、Prefab overrideと作業Scene変更をホストへ通知します。既存メニューassetはそのassetを保存します。配置と既存Scene componentはホストのAvatar Prefab保存を使用します。通常生成項目の削除はGameObjectと付属component、既存MA Menu Itemの削除はそのcomponentだけを除去します。Scene、Git、DBは機能側で保存しません。

## 依存

Coreの公開Localization・ProjectAssetSettings、UI、共有AvatarEditingの編集許可・変更通知・単独Windowへ依存します。設定サービス型のためCore.Contracts、BodyPartCategoryのためCore.Editorも参照します。AvatarEditingは統合版・単独版の対象と保存契約を揃えるため使用します。他のAvatar機能へ参照しません。VRChat SDK、MA runtime、GM runtime / Editorの実際に使うassemblyのみ参照します。GMは描画の共用に使用し、Edit Modeでアバター実行モジュールを生成しません。

MAは`src/package.json`の対応範囲（1.18.2以上2.0.0未満）で内部resolver `VirtualMenu.ForAvatar`、`RootMenuNode`、Childrenのnode keyへアクセスします。バージョン依存箇所はExpressionMenuModelへ隔離します。resolver取得・解決失敗時はエラーを表示し、不完全な合成メニューへの編集へ代替しません。
