# PhysBone Collider

保存済みCollider設定の読み戻しは、現在のLayout IDから生成するObject名だけで対応付けます。旧形式のボーン一致による設定の読み替えは行いません。

## 公開API

`PhysBoneColliderApi`は、UIと同じ検出・配置・適用処理を外部integrationから呼ぶ公開境界です。Avatar、対象root、配置preset、最小bone長から候補とPhysBone一覧を返し、調整後の位置、回転、半径、長さ、追従boneと割り当て選択を既存gatewayへ渡します。

このAPIはEditor UIなどのプロジェクト内integration向けです。PhysBone Colliderの操作はMCPへ公開しません。

## 機能

`ee4v/Window/Avatar/PhysBone Collider Setup`から、シーンまたはPrefab Mode上のアバターへカプセル形のVRC PhysBone Colliderを設定します。統合ee4vウィンドウでは「PhysBone」カテゴリとして同じ画面を埋め込み、選択中の派生Prefabへ設定を保存できます。探索対象はPrefabルート直下にある、名前が`Armature`の子オブジェクトだけです。大文字と小文字は区別しません。衣装など別階層のArmatureは初期探索へ含めません。

Armature内ではSkinnedMeshRendererが参照する変形ボーンを調査します。`EditorOnly`タグを持つ階層は対象外です。VRC SDKの`IEditorOnly`またはNDMFの`INDMFEditorOnly`を実装するコンポーネントを持つ階層も除外します。

配置密度には次の3つのプリセットがあります。

- 軽量: 胴体の上下、頭、左右の腕、左右の脚を基本とする7個へまとめます。腕は上腕から手、脚は太腿から足までを1個のカプセルで覆うため、基準姿勢から肘や膝を大きく曲げると通常とは追従範囲が異なります。
- 通常: 現行の自動配置と同じく胴体、頭、肩、腕、脚の主要ボーンを使います。HumanoidではUnityの割り当て、その他ではボーン名から主要部位を判定します。目、顎、指、つま先は対象外です。
- フル: 主要部位に限定せず、Armature内の可視な変形ボーンを候補にします。最小ボーン長による除外はほかのプリセットと同じです。

腕と脚は、次の主要ボーンまでの距離が最小ボーン長以上の区間だけを候補にします。しきい値未満の区間は一覧とプレビューに表示しません。カプセルの中心は区間中央、全高は区間長、半径は区間長の18%を初期値にします。半径の上限は0.25mです。

胴体では短いSpine区間を個別に判定せず、HipsからChestまでとChestからNeckまでへまとめます。下側の半径は左右の脚付け根幅、上側の半径は左右の上腕付け根幅から求めます。これにより短いSpineがしきい値未満でも、Chestだけではなく腹部と胸部を覆う2つのColliderを提案します。ローカルY軸を区間の終点へ向ける回転も自動設定します。再検出すると現在のプリセットとしきい値から提案を作り直します。ee4vが以前に生成した同じ候補がある場合は、追従ボーン、半径、全高、位置、回転を読み戻します。

## 編集画面のライフサイクル

単独Windowと統合ee4vウィンドウの埋め込み画面は、通常のC#クラスである`PhysBoneColliderEditor`を共有します。`PhysBoneColliderWindow`は単独表示のホストだけを担当し、埋め込み用の非表示`EditorWindow`は生成しません。これによりUnityのレイアウト検証で親のないWindowが`Invalid editor window`として検出されることを防ぎます。

ホストの終了または埋め込み画面の破棄時に編集クラスを`Dispose`し、Previewと`ScenePreviewViewport`を解放して、編集用に読み込んだPrefab Contentsをアンロードします。埋め込みの初期化に失敗した場合も、生成途中の編集クラスを破棄します。

## プレビューと適用

専用画面はアバター全身に候補を重ねて表示します。ワイヤーを常にアバターより手前へ描く透視表示にするため、体の裏側にあるカプセルも確認できます。水色は有効なCollider候補、中心マーカー付きの黄色は一覧で選択中の候補です。選択中のColliderへ割り当てたPhysBoneのTransformはピンク色で表示し、対象一覧で選択中の1件は黄緑色で強調します。割り当てを解除したPhysBoneは表示しません。ColliderとPhysBoneの表示はそれぞれ個別に切り替えられ、値の変更時にワイヤーと再描画へ同期的に反映します。生成設定では配置密度と最小長を変更できます。Collider候補はボーン階層を挟まない一覧で表示します。

一覧から作成対象を切り替え、選択したカプセルの追従ボーン、半径、全高、位置、回転を編集できます。追従ボーンを変えたときはワールド上の配置を維持したまま、新しいボーンのローカル座標へ変換します。「配置をリセット」では追従ボーンを含む配置値を現在のプリセットの提案へ戻します。右ドラッグでプレビューを回転し、中ドラッグで移動します。ホイールで拡大または縮小します。

単独Windowでは対象PhysBoneをアバター全体から自動検出しません。「検出対象を追加」でシーン上のGameObjectを複数設定して検出すると、各GameObject直下にある、名前が`Armature`の子階層内だけからPhysBoneを検出します。ee4vウィンドウでは派生Prefab rootを最初の検出対象として設定し、その直下のArmatureから初期検出します。`Armature`の大文字と小文字は区別しません。さらに深い階層にあるArmatureや、Armature外のPhysBoneは対象にしません。検出対象が重なっても、同じPhysBoneは重複させません。各Colliderには検出したPhysBoneのRoot Transformを個別に設定できます。同じRoot Transformを使うPhysBoneが複数ある場合は1行へまとめ、選択するとそのすべてへ割り当てます。新しいCollider候補では検出した対象を初期選択します。適用済みの生成物がある場合はPhysBoneの参照から選択状態を読み戻します。適用時も現在の検出範囲外にあるPhysBoneへは割り当てません。通常時は候補数の通知を表示せず、選択が必要な状態、エラー、適用結果だけを画面上部へ通知します。

設定Panel、候補一覧、PhysBone一覧はCore UIと同じ境界線、面、角丸、hover、選択状態を使用します。3D PreviewはCore UIの`ScenePreviewViewport`をee4vウィンドウの見た目カテゴリと共有し、グリッド背景、背景の明暗切り替え、表示リセット、未表示時のPlaceholderを同じ部品から構成します。ColliderとPhysBoneの表示切り替えは`FeatureOverlay`へ、Avatar・Collider・Bone描画は描画callbackへ重ねます。左下の操作説明は表示しません。この構成は埋め込み表示と単独Windowで共有します。

適用時はアバター直下へ`<Avatar名>_PhysBoneColliders`という1つのPrefabを作り、名前が`[ee4v] PhysBone Collider`で始まる生成物をその中へまとめます。各ColliderにはModular AvatarのBone Proxyを設定し、ビルド時に選択した追従ボーン直下へ移動させます。VRC PhysBone ColliderのRoot TransformはCollider自身、Shape TypeはCapsuleです。生成Prefabは共通生成アセットルートの`Avatar/PhysBoneCollider/<Avatar名>`へ保存します。

再適用では同じ生成Prefabの中身を置き換えます。現在の生成Prefab内のColliderだけを置き換え、その参照を先に除去します。旧方式でボーン直下へ作成した生成物の移行・除去は行いません。利用者が作成したColliderには触れず、画面で選択したPhysBoneだけへ現在のCollider参照を追加します。ee4vウィンドウでは派生Prefabを`LoadPrefabContents`で一時編集し、適用成功後に同じPrefab Assetへ保存してから一時編集コンテキストを破棄します。

VRChat SDKとModular Avatarへコンパイル時依存は持ちません。どちらかがない環境でも提案とプレビューを利用でき、適用だけを無効にします。シーンまたはPrefab Mode上の操作はUnityのUndoで取り消せます。ee4vウィンドウから派生Prefab Assetへ保存した変更は通常のScene Undo対象にはなりません。
