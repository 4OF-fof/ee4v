# Avatar編集の共有境界

`src/Editor/Feature/Shared/AvatarEditing`の`Ee4v.AvatarEditing.Editor`をAvatarParts、AvatarMaterials、AvatarInfo、FaceExpressionとAssetManagerの統合ホストが使用します。PartsとMaterialsは同じ対象・選択・Preview・変更通知を共有し、AvatarInfoは単独Windowの対象入力とPreviewのライフサイクルを共有するために使用します。FaceExpressionは自身が所有するBlendShapeプリセットを中立な名前分類の契約へ提供するために使用します。

`AvatarEditingContext`は対象・共通選択・Previewとフィードバックの状態を保持し、`AvatarEditingServices`と`AvatarEditingHost`をコンストラクターで受け取ります。機能が保持する体型・パーツ・Materialのキャッシュは含めません。Windowの再構築時にはControlsHostとPreviewを差し替えます。

`Context.Edits`は編集可否、保留変更の確定、Asset path、Sceneの変更通知、保存可能状態の通知、失敗表示とMaterial作成を提供します。必須サービスは構築時にnullを拒否し、後から差し替えません。Material Inspectorの変更通知だけは機能の構築後に設定できます。

`Context.Host`は画面更新、再構築、キャッシュ破棄、再描画とPreview選択の同期を必須として受け取ります。PartsとMaterialsの表示先は既定で画面更新と同じです。Prefabグループの装飾・更新、カテゴリの無効化、パーツ名の除外などは任意の連携です。単独Windowでは既定の動作を使用し、統合ホストは必要な連携だけを設定します。名前分類は既定で`AvatarShapeNaming.Create`を使用します。

編集コンポーネント自身はSceneやアセットの保存先を決めません。作業対象への変更はUndoへ記録し、`Edits.WorkingSceneDirtyChanged`と`Edits.Changed`を通知します。統合版の保存・保護・Variant管理と機能間更新はAssetManagerホストが、単独版の読み込み・保存は`AvatarPrefabEditorWindow`が調整します。`ClearData`は機能内部のキャッシュだけを消去し、ホストの無効化通知を呼び返しません。

単独Windowの`PrepareFeatureSave`は、保留変更の確定後、Prefabへの適用前だけに呼びます。機能固有の保存準備が失敗した場合は適用を中止します。表示更新・対象切り替え・終了・変更を戻す操作では呼びません。AvatarPartsはここでアバター全体のBlendShape同期設定を確定します。

`AvatarBodyAnalysis`はHumanoidの部位対応、BlendShape名の分類と部位の絞り込みを共有します。Coreの`BodyPartCategory`と`PrefabHierarchyUtility`を使用します。`AvatarEditingUi`と`avatar-editing.uss`はフィードバック、空状態、Prefabグループの表示規則を共有します。空状態は共通UIの`EmptyState`を使用し、呼び出す機能が自身のLocalization scopeで翻訳した見出しと説明を渡します。共有ホストの翻訳は`avatarEditor`、体型・パーツとMaterialの翻訳はそれぞれの機能が所有します。

部位の遷移先は、フォーカス用boneと選択範囲内の対応Meshの両方が存在する場合だけ有効にします。`GetMeshBodyPartCategories`はMeshを持つRendererだけを走査し、SkinnedMeshは描画に使う頂点の最大weightのboneから部位を判定します。bone配列に含まれるだけの未使用boneは判定へ含めません。boneの分類にはアバター全体のHumanoid対応を使い、構成Item外のboneへ追従する衣装も対象にします。weightを読めないMeshと通常のMeshRendererは名前と親階層の部位分類を使用します。active状態やPreviewの一時的な非表示は存在判定から除外せず、非表示パーツを再度編集できる状態を保ちます。空MeshとMesh未設定のRendererは含めず、分類不能なMeshは全身で扱います。統合画面と単独Prefab編集で同じ判定を使用します。

`IAvatarShapeNaming`と`AvatarShapeMapping`は特定の表情エディターに依存しない名前分類の契約です。FaceExpressionの`AvatarShapeNamingProvider`が`AvatarShapeNaming`へfactoryを登録し、統合版と単独版の両ホストが`AvatarShapeNaming.Create`で分類器を生成します。プリセットと区切り文字設定の変更は同じ`AvatarShapeNaming.Changed`で通知します。AvatarPartsからFaceExpressionへの参照はありません。分類器が未登録なら状態を持たない共通の未分類器を使用します。

## BlendShapeのお気に入り

`AvatarEditingUi.CreateBlendShapeFavoriteIcon`で両画面の星表示を統一します。20px用のFluent UI StarのPNGを12pxで描画し、24pxの操作領域の中央に配置します。RegularとFilledは同じ輪郭のSVGを使用します。未選択は輪郭を通常の文字色で表示し、選択時はFilled Starを黄色（#FFCD40）で表示します。選択状態の背景色ではなく、星の形と色で状態を示します。

`BlendShapeFavorites`はAvatarPartsとFaceExpressionが使用します。機能間で同じお気に入りを表示するため、meshのAsset GUID・local file IDと正確なBlendShape名を共通キーにします。値はユーザーのEditorPrefsへ保存し、Prefabやクリップへ書き込みません。保存対象のない一時meshはsessionのinstance IDを使用します。meshの識別情報は弱参照のキャッシュへ保持し、同じmeshについてAssetDatabaseへ繰り返し問い合わせません。EditorPrefsの読み取り結果はEditor session内でキャッシュし、Toggleは永続化とキャッシュ更新を完了してから変更キーを`KeyChanged`で即時通知し、一覧構成の更新を`Changed`で通知します。行は一致するキーの星だけを即時更新します。お気に入り操作はBlendShapeの値・クリップへの使用状態を変更しません。

## 単独Prefab編集

`AvatarPrefabEditorWindow`はHierarchyのPrefabインスタンス入力、Preview、部位選択とPrefabへの保存を共有します。AvatarPartsには「変更を戻す」を表示し、AvatarMaterialsには表示しません。WindowはAssetManagerのDB・Variant一覧・専用作業Sceneや他のWindowを必要としません。

部位選択を表示する単独Windowは、初期の全身表示から部位ポーズを適用します。頭・胸・手などの移動ではCameraとポーズを連動させ、共通Previewの「Tポーズ」で基準姿勢と部位ポーズを切り替えます。全部位の仮ポーズとHumanoidの対応範囲は[Previewの契約](../core/avatar-preview.md)に従います。

AvatarInfoは同じホストで情報表示、Unity内の名前編集とBlueprint IDの選択補助を提供します。部位選択と変更を戻すボタンは表示せず、ID等のPrefab overrideの保存に共通の「Prefabに保存」を使います。Prefab rootの名前はdefault overrideなのでScene保存で保持します。

入力は通常Scene上の接続済みPrefabインスタンスです。子を指定した場合は最寄りのPrefabインスタンスrootへ正規化します。ProjectのPrefabアセット、Prefab Mode、接続が失われたインスタンスは受け付けません。初回はHierarchyの選択から対象を設定できます。対象はそのまま編集し、独立したPrefab contentsへ読み込まないため、Hierarchyや統合Windowが同じインスタンスを使っていれば変更を共有します。Previewは同じSceneインスタンスをCoreの[AvatarPreviewRenderer](../core/avatar-preview.md)で描画します。描画用の表示切替と未確定の編集値は対象へ保存しません。

書き込み可能なPrefabとPrefab VariantはEdit Modeで編集し、「Prefabに保存」で保留変更を確定して`ApplyPrefabInstance`を実行します。保存先は対象インスタンスに接続された元Prefabです。Model Prefab、NotEditable指定や書き込み不可の対象は読み取り専用です。保存可能かどうかは、保留変更とCoreの`PrefabEditingChanges.HasContentOverrides`による実際のPrefab差分で判定し、有効なボタンは共通UIの青い主操作表示を使用します。

「変更を戻す」は確認後に保留変更を取り消し、`RevertPrefabInstance`でインスタンス全体を現在の元Prefabの保存内容へ戻します。このWindow以外で追加した対象内のoverrideも戻します。読み込み時のスナップショットやGit版は基準にしません。Materialアセットのプロパティは復元しません。

Material Inspectorは割り当て先アセットを直接編集し、単独Materials Windowでは変更したMaterialを個別に書き出します。Materialの変更は通常のUndoで戻せます。Materialの割り当て変更はインスタンスのoverrideなので、Prefabへの保存は必要です。

切り替え・終了・assembly reload前には保留変更をインスタンスへ反映します。Windowは対象を破棄したり元に戻したりせず、専用の未保存確認も表示しません。インスタンスの変更は通常Scene内に残ります。WindowはSceneの作成・読み込み・保存・終了とGitへの版保存を行いません。Sceneの保存はUnity、Variantの版保存はAssetManager統合ホストが管理します。

単独Windowの共通スタイルは`avatar-prefab-editor.uss`で読み込みます。翻訳は各機能のnamespaceと一致するLocalization scopeに置き、共有ホストの文字列はAvatarEditingが所有します。
