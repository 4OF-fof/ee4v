# Avatar編集の共有境界

`src/Editor/Feature/Shared/AvatarEditing`の`Ee4v.AvatarEditing.Editor`をAvatarParts、AvatarMaterials、AvatarComposition、FaceExpressionとAssetManagerの統合ホストが使用します。PartsとMaterialsは同じ対象・選択・Preview・変更通知を共有し、Compositionも単独Prefab編集のライフサイクルを共有します。FaceExpressionは自身が所有するBlendShapeプリセットを中立な名前分類の契約へ提供するために使用します。

`AvatarEditingContext`は対象と共通選択状態、編集可否、保留変更の確定、保存可能状態の通知、UI再構築とPrefabグループの表示操作を渡す境界です。機能が保持する体型・パーツ・Materialのキャッシュは含めません。ホストは機能の呼び出し前に利用するサービスを設定し、Windowの再構築時にControlsHostとPreviewを差し替えます。

編集コンポーネント自身はSceneやアセットの保存先を決めません。作業対象への変更はUndoへ記録し、`WorkingSceneDirtyChanged`と`Changed`を通知します。統合版の保存・保護・Variant管理と機能間更新はAssetManagerホストが、単独版の読み込み・保存は`AvatarPrefabEditorWindow`が調整します。`ClearData`は機能内部のキャッシュだけを消去し、ホストの無効化通知を呼び返しません。

`AvatarBodyAnalysis`はHumanoidの部位対応、BlendShape名の分類と部位の絞り込みを共有します。Coreの`BodyPartCategory`と`PrefabHierarchyUtility`を使用します。`AvatarEditingUi`と`avatar-editing.uss`はフィードバック、空状態、Prefabグループの表示規則を共有します。

`IAvatarShapeNaming`と`AvatarShapeMapping`は特定の表情エディターに依存しない名前分類の契約です。統合版ではAssetManagerの`WorkflowShapeNaming`がFaceExpressionのプリセット公開APIへ接続します。単独版ではFaceExpressionの`AvatarShapeNamingProvider`が`AvatarShapeNaming`へfactoryを登録し、ホストが分類器を生成します。AvatarPartsからFaceExpressionへの参照はありません。分類器が未登録なら未分類として扱います。

## 単独Prefab編集

`AvatarPrefabEditorWindow`はPrefab入力、Preview、部位選択、保存ボタンと未保存変更の確認を共有します。WindowはAssetManagerのDB・Variant一覧・作業Sceneや他のWindowを必要としません。入力はProjectのPrefabに限り、`LoadPrefabContents`で独立した編集領域へ読み込みます。通常SceneやPrefab Modeのオブジェクトを編集対象にしません。

書き込み可能なPrefabとPrefab VariantはEdit Modeで編集し、保存ボタンで入力したPrefabへ`SaveAsPrefabAsset`を実行します。Model Prefab、NotEditable指定や書き込み不可の対象は読み取り専用です。Prefab切り替えと終了時には未保存変更を確認します。破棄は編集領域を再読み込みし、切り替えと終了では領域とPreviewを解放します。入力Prefabと編集中の内容はassembly reloadをまたいで維持します。

Material Inspectorは通常のInspectorと同じく割り当て先のMaterialアセット自体を編集します。Prefabの変更破棄はMaterialアセットの変更を戻しません。Materialプロパティの変更はUndoで戻し、単独版の保存時には使用中の編集可能なMaterialも保存します。

単独Windowの共通スタイルは`avatar-prefab-editor.uss`で読み込みます。翻訳は各機能のnamespaceと一致するLocalization scopeに置き、共有ホストの文字列はAvatarEditingが所有します。
