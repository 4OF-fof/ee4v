# AvatarInfo

`src/Editor/Feature/Avatar/AvatarInfo`がアバターの詳細タブを所有します。表示と解析は`Ee4v.AvatarInfo.Editor`、NDMFとの接続は`Ee4v.AvatarInfo.Ndmf.Editor`、VRChat SDKとの接続は`Ee4v.AvatarInfo.Sdk.Editor`です。SDK接続はAvatars SDKがある場合だけコンパイルされ、`IAvatarInfoSdk`を登録します。AssetManager以外の機能モジュールへ依存しません。

## 名前とアップロード先

`AvatarInfoView`は「名前」、名前で選択するアップロード先、同期パラメーター使用量、装着警告と性能情報を表示します。Blueprint IDの入力・表示欄は提供せず、選択した項目のIDを内部的にPipelineManagerへ設定します。`AvatarInfoEditing.CreateOptions`がホストの`AvatarEditingContext`を編集操作へ接続します。編集可否はホストのPrefab編集条件に従い、Play Mode中は編集しません。

名前は対象ルートGameObjectの名前です。空白だけの名前は受け付けず、変更をUndoへ記録してSceneをdirtyにします。Prefabアセットのファイル名とVRChat上の登録名は変更しません。UnityのPrefab root名はdefault overrideなので「Prefabに保存」の対象にならず、インスタンス名はScene保存で保持します。

Blueprint IDは`AvatarInfoAnalysis.GetBlueprintId`で対象ルートの`VRC.Core.PipelineManager.blueprintId`から読みます。子や元PrefabのIDへフォールバックしません。「新規アバター」または取得した自分の登録済みアバター名から、階層のない一覧で選択します。名前中の`/`はメニュー上だけ全角`／`へ置き換え、同名項目には番号を付けて区別します。取得前の設定済みIDは「設定済みアバター（一覧未取得）」として表示します。ドロップダウンは初期状態、取得中、取得失敗時に無効で、一覧取得が成功した場合だけ選択可能になります。空の一覧を正常取得した場合も「新規アバター」は選択できます。

「一覧取得」を明示的に押したときだけ、SDKのログイン状態を確認し、ログイン中のアカウントについてSDK標準の`ApiAvatar.FetchList`を呼びます。未ログインなら取得せず、ユーザーがControl Panelで手動ログインしてから再度取得します。拡張はControl Panelを開きません。通常時はアップロード先の下に補足や進捗テキストを表示しません。取得中はボタンのラベルを変更し、結果とエラーの詳細は取得ボタンのtooltipへ表示します。未ログインまたは一覧取得に失敗した場合だけ、アップロード先の下へ共通`MessagePanel`のWarning通知を表示し、Control Panelを一度開いてログイン状態を確認してから手動で再取得するよう案内します。再取得開始時に通知を消し、キャンセル時は失敗通知を出しません。

認証情報は要求・取得・保存せずSDKへ任せ、独自HTTPクライアントやSDKの認証・User-Agent設定変更は行いません。20件ずつ取得し、ページ間隔を置き、成功した一覧はアカウント単位で5分間共有します。定期取得や自動再試行はせず、失敗後は1分間追加取得を抑制します。取得途中のアカウント変更は破棄し、Viewのdetachで残りのページ取得を取り消します。発行済みのSDKリクエスト自体は中断できません。

選択するとローカルのPipelineManagerへIDを設定します。必要なPipelineManagerの追加も含めUndoに対応します。既存IDの割り当ては同じログインアカウントで取得した自分の一覧に限定します。「新規」はローカルIDを空にする操作です。サーバー上のアバター作成は、ユーザーが公式SDKで手動アップロードした時に行われます。拡張はSDKのログイン、AssetBundleビルド、テスト、アップロード、サーバー上の登録内容変更のAPIを呼びません。

公式[Creator GuidelinesのAPI Usage / Bots](https://hello.vrchat.com/creator-guidelines#api-usage-bots)はAPI利用を条件付きで認め、代理アップロード、認証情報の要求・保管、無制限の反復要求などを禁止しています。この機能はSDK内のユーザー操作による読み取りとローカル入力補助に限定する設計判断です。特定の拡張への公式な承認を意味しません。[Public SDK API](https://creators.vrchat.com/sdk/public-sdk-api/)に公開されているビルドイベントを使用し、SDKのボタンや内部UIを操作しません。

## 取得する情報

装着警告は追加されたアバター直下のPrefabインスタンスにMerge ArmatureとBone Proxyがない場合に表示します。ベースPrefab由来の子と、共有`AvatarGeneratedPrefabs.IsExpressionMenu`で識別するExMenu生成Prefabは除外します。統合版と単独AvatarInfo Windowで同じ判定を使用します。

`AvatarInfoAnalysis`は装着警告、AAOの有無とVRChatの性能情報を取得します。性能はEdit Modeで「測定」を押したときだけ取得します。`AvatarPlayModePerformanceCache.Bake`からNDMF接続を呼び、対象のコピーをPreview SceneでNDMFの全フェーズ（AAOを含む）に通します。処理成功後のコピーからPC／Quest性能結果、同期パラメーター使用量とアイテム別内訳、取得日時をSessionStateへ保持します。元のアバターは変更せず、コピー、Preview Sceneと測定ごとの専用フォルダーに作成した生成アセットは終了時に解放します。他のNDMFビルドの生成アセットは削除しません。SDKまたはNDMFがない場合、Play Mode中とその切り替え中、測定中はボタンを無効にします。失敗した場合は前回の成功結果と取得日時を保持してエラーを表示します。Play Modeへの移行、SDKビルド、画面表示とPC／Questの切り替えでは自動測定せず、最後の手動測定結果を表示します。

パラメーターはベイク後の最終DescriptorのExpression ParametersをSDKの`CalcTotalCost`で計算し、上限もSDK定数から取得します。測定結果の値がなければ現在のDescriptorを使い、表示ラベルで区別します。標準Expressionsの場合はSDK標準パラメーターを使用し、取得不能な値をゼロ扱いしません。

アイテム別内訳の供給元はNDMFの`ParameterInfo`から取得します。供給元Componentが属するアバター直下のGameObjectを衣装・ギミックの単位にし、直下の階層位置を識別に使うため同名アイテムも混同しません。Descriptorなどルート上の供給元は「アバター本体・共通」とします。Modular AvatarのTransforming処理前に供給元とリネーム後の名前を記録し、処理後・Component除去前に自動生成されたMenuパラメーターを補足します。ビルド後は最終Expression Parametersの各パラメーターのSDK計算値を供給元へ集計し、削除されたパラメーターを含めません。照合できない値は「その他（供給元不明）」へ計上します。共通パラメーターはNDMFが解決した最初の供給元へ一度だけ計上します。

現在値の内訳は追加予定のパラメーターを含むNDMFの`BitUsage`による推定です。内訳がある場合はカードの合計値とバーにもその推定合計を使い、カード見出しに「ビルド前の推定」と明記して凡例の合計と一致させます。凡例の上に推定値の補足説明文は表示しません。標準ExpressionsではSDK標準パラメーターを本体の使用量とします。同期しないパラメーターと使用量0のアイテムは内訳に表示しません。供給元を保持していない過去のビルド記録では未取得の案内を表示し、現在の構成を過去の内訳として使いません。NDMF接続assemblyはAvatars SDKがある場合だけコンパイルされ、`nadena.dev.ndmf.vrchat`の公開APIを使用します。

`AvatarBuildSizeCache`はユーザーが公式SDKで開始したビルドの公開イベントを受け、成功時だけ出力AssetBundleのファイル長をダウンロードサイズとして記録します。展開後サイズはSDKの検証ヘルパーから取得し、不明なら未取得とします。SDKパネルが開いている場合だけビルダーへ接続し、ビルドやアップロードを呼びません。PC／Quest別に最後の成功値と取得日時をSessionStateへ保持します。Play ModeのNDMFビルドだけではサイズは取得しません。性能とサイズの日時は別々に表示し、異なるビルドの結果を同時刻の結果として扱いません。表示サイズは1024² bytesをMBとして表記します。

両キャッシュの`Get`と`Changed`を通して結果を読み、更新通知を受け取ります。対象のScene・階層位置・Prefab GUIDを識別キーに使い、名前変更で結果を見失わないようにします。Play Mode直前には対象の識別情報だけを別に記録します。`FindPlayModeAvatar(scenePath, prefabPath)`は呼び出し側が指定したScene内でその記録に対応する対象を検索します。Play Mode開始時に測定結果を消しません。AssetManager固有の作業Sceneパスは生成しません。

## ホストとCatalog

ビルド結果のパラメーターカード見出しは「同期パラメーター」とし、ビルド後の補足は付けません。最下部の性能結果の日時ラベルは「取得日時」、サイズの日時ラベルは「サイズの取得日時」とします。

同期パラメーター、ダウンロードサイズと展開後サイズは共通`InfoCard`を使い、既存の性能カードと同じ枠、面、余白へ揃えます。パラメーターは総合評価カードの直下の幅いっぱいのカードに使用量と上限を表示します。使用量バーはアイテムごとのbit数に比例した色付き区間へ分け、直下の凡例に同じ色の印、アイテム名、bit数を使用量の多い順で常時表示します。本体・共通は鮮明な緑、供給元不明はマゼンタを使い、空き容量は共通の`SurfaceRaised`の背景色と凡例で対応させます。上限超過はカードの枠と面をエラー色にし、バー全体を使用量で正規化して全アイテムの比率を維持します。供給元未取得時は既知の合計値を供給元不明として表示します。長いアイテム名は折り返し、tooltipで階層位置を確認できます。サイズは2列のカードで表示し、狭い領域では折り返します。追加カードは値が取得できた項目だけを表示し、全項目未取得なら空のグリッドも追加しません。性能とサイズの取得日時はカードを使わず、性能項目やエラー通知より後の最下部に補足テキストとして個別に表示します。日時は日付と時刻を同じ行に記載し、狭い領域では折り返します。日時がない項目と、両日時がない場合のフッターは表示しません。

「測定」ボタンはアバターパフォーマンスの見出しの横に表示し、測定中は「測定中…」とします。手動測定の案内は総合評価カード内の「未取得」の直下に折り返し可能な本文として表示します。別の案内カードは表示しません。性能取得失敗と装着警告は、表情機能と同じ共通`MessagePanel`で表示します。取得失敗はError、装着警告はWarningを使い、説明文を折り返します。装着設定を開くボタンは警告の下に表示します。

パラメーターバーのアイテム色は青、橙、青緑、紫などの彩度を抑えた固定パレットを使用し、Unity Dark／Lightそれぞれで背景に合う明度にします。アイテムの階層識別子順に色を割り当て、使用量による並べ替えでは色を変えません。本体・共通と供給元不明には通常アイテムと異なる色相の不透明な専用色を使用し、通常アイテムの色の順番に影響させません。アイテム数がパレットの色数を超える場合は明度違いを使用します。バー区間の境界を空き容量と同じ背景色の細い線で区切り、凡例の色と一致させます。

単独Windowのメニューは`ee4v/Window/Avatar/Avatar Info`です。`AvatarInfoWindow`は共有`AvatarPrefabEditorWindow`のHierarchy入力とPreviewを使い、AssetManagerと同じView、編集補助、PC／Quest切替を提供します。部位選択と変更を戻すボタンは表示せず、Blueprint ID等のPrefab overrideに対して「Prefabに保存」を表示します。Scene保存とGit保存は行いません。装着設定を開く操作はホストがSelectionとInspectorへ接続します。Viewはそれらを操作せず、`UI/avatar-info.uss`を自身で読み込みます。

Catalogは`Domain/AvatarInfo/Displays/AvatarInfoView`へ登録します。Storyでは名前編集、一覧取得前の選択不可、サンプル一覧取得後のID選択と新規選択、ID設定有無、結果の有無、PC／Quest切替、アイテム別の色分けバーと凡例、ビルド前の推定表示、測定ボタンからサンプル結果への切り替えを確認できます。StoryはScene編集、SDKへの通信、ベイク、ビルド、Play Mode切替を実行しません。
